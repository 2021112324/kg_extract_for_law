# 国家标准知识图谱数据转知识条目规则设计

> 设计依据：国家标准原始数据、`national_standard/prompt/schema.py`、国家标准两阶段抽取结构、当前批次 `node.json`/`edge.json` 实际图谱数据及现有知识图谱转知识条目规则。
>
> 核心原则：**以标准原文中的完整规范单元为知识主体，以语义实体为主要入口，以结构节点和资源节点保障原文覆盖，不把分类标签、定位字段或模型概括单独包装成知识。**

---

## 1. 数据特点与设计目标

当前国家标准原始数据共包含 16 份标准。每份标准除正文外，还可能包含封面、前言、引言、目录、规范性引用文件、术语和定义、正文要求、附录、参考文献、表格、图片及流程图。不同标准的篇幅、层级深度和资源数量差异较大，单纯按照“实体 + 属性 + 属性值”逐项转写，会产生大量不完整、重复或缺少原文语境的伪知识。

当前图谱导出数据与 16 份原始标准一一对应，共包含 5,036 个节点和 5,506 条关系。实际业务节点分布如下。该统计用于确定转化入口和校验门槛，不代表所有节点都必须产出知识。

| 业务节点类型 | 节点数 | 关键字段实际情况 | 转化定位 |
| --- | ---: | --- | --- |
| 标准文件 | 16 | 文件名称、编号、性质、发布实施信息均有值，部分扩展属性非全量 | 形成少量文件档案知识 |
| 标准结构节点 | 1,530 | 1,352 个节点具有节点内容，附录已并入该类型 | 恢复上下文并补充原文覆盖 |
| 术语定义 | 177 | 术语名称和定义内容均有值 | 核心知识入口 |
| 标准要求 | 1,959 | 要求内容及主要结构化字段均有值 | 核心知识入口 |
| 指标限值 | 190 | 187 个具有限值，3 个只有指标名称和要求性原文 | 通过限值完整性校验后产出 |
| 试验检测方法 | 88 | 方法名称和方法内容均有值，但仍需语义角色校验 | 通过方法语义校验后产出 |
| 标准依据 | 271 | 主要属性基本完整 | 仅通过文件级依据关系产出 |
| 引用标准 | 536 | 包含外部标准、内部条款、自身引用以及少量误分类对象 | 归一化后通过引用关系产出 |
| 表格 | 100 | 98 个有表格内容，93 个同时存在相同的 HTML 副本 | 保留一份完整表格内容 |
| 流程图 | 16 | 均保存 Mermaid 内容及描述字段 | 校验 Mermaid 后产出 |
| 图片 | 153 | 保存图片链接和类型 | 只作附件，不单独产出 |

原始数据中的 16 份标准均已形成标准文件节点，文件级覆盖完整。原始资源中图片数量多于图谱图片节点数量，因此图片附件只能按图谱中已建立的图片节点、包含关系和结构节点图片地址进行挂接；图片资源覆盖差异不影响自然语言知识正文的生成，但应单独记录为资源完整性问题。

国家标准知识条目转化需要实现以下目标：

1. 完整保留标准中能够独立核验的要求、定义、指标、检测方法和引用依据。
2. 避免把标准编号、章节路径、节点类型、风险标签等管理字段单独转成知识。
3. 对未形成独立语义实体的说明性原文，通过标准结构节点内容提供覆盖。
4. 对表格、流程图和图片采用适合其信息形态的处理方式，避免丢失表格指标或把资源地址误当作知识。
5. 控制标准要求、结构节点原文和表格内容之间的重复。
6. 对实际图谱中的误分类节点、内部直接引用和异常关系先归一化或过滤，避免把抽取误差继续转写成自然语言知识。

## 2. 国家标准知识的判定标准

一条国家标准知识应当是标准文件在特定结构位置中，对某个对象的事实、定义、要求、指标、方法或引用关系所作的**完整、可验证、可复用**表达。

能够作为知识条目的内容主要包括：

- 标准明确规定的适用范围、制定目的和文件状态；
- 对术语的完整定义；
- 对主体、产品、材料、设备、过程或文件提出的完整要求；
- 带有适用对象、数值边界、单位或条件的指标限值；
- 用于试验、检测、测定、检验、监测或符合性判定的方法；
- 标准原文中明确存在的依据、引用和内部指向关系；
- 无法归入上述语义对象，但本身具有完整含义的标准条文、注释或说明；
- 原始表格和有效流程图中能够被核验的完整内容。

以下内容不应单独作为知识条目：

- 节点编号、节点路径、节点类型、页码、资源 ID 等结构定位信息；
- 合规风险类型、要求类型、量化特征等分类或检索标签；
- 只有标题而没有正文的章节节点；
- 只有图片链接、图片类型或内部文件名的图片节点；
- 由模型概括但无法回到原文核验的推断性描述；
- “某节点包含某节点”“某章节规定某要求”等纯图谱组织关系；
- 从标准主题推断出的经济行业、合规域或适用场景。

## 3. 知识产出类型

| # | 知识类型 | 主要来源 | 产出原则 |
| --- | --- | --- | --- |
| 1 | 标准文件档案知识 | 标准文件属性 | 对明确文件信息分组组装，不逐属性输出 |
| 2 | 标准范围与目的知识 | 标准文件属性或对应结构节点原文 | 原文优先，摘要只作兜底 |
| 3 | 术语定义知识 | 术语定义 | 一个术语形成一条完整知识 |
| 4 | 标准要求知识 | 标准要求 | 以要求内容为正文，一个完整要求一条知识 |
| 5 | 指标限值知识 | 指标限值 | 必须具有可核验限值；原文优先，必要时按结构字段组装 |
| 6 | 试验检测方法知识 | 试验检测方法 | 必须表达试验、检测、测定、检验、监测或判定方法 |
| 7 | 结构节点原文知识 | 标准结构节点 | 只补充未被语义实体覆盖的完整原文 |
| 8 | 表格知识 | 表格 | 保留表题、表格内容和必要表注，不拆造无依据行知识 |
| 9 | 流程图知识 | 流程图 | 仅有效 Mermaid 流程图产出，保留原始流程内容 |
| 10 | 引用知识 | 依据、引用关系 | 仅对原文明示的关系产出 |

图片不作为独立自然语言知识类型。图片链接作为相关结构节点、表格或流程知识的附件信息保留。

## 4. 总体转化流程

```text
读取并解析 Neo4j 导出的节点和关系
        ↓
按 filename 划分单份标准子图
        ↓
归一化业务类型、关系端点和内部引用
        ↓
恢复标准文件、结构节点及语义实体的上下文
        ↓
生成文件档案、术语、要求、指标、方法和引用知识
        ↓
识别已被语义实体覆盖的结构节点原文范围
        ↓
补充未覆盖的结构节点原文、表格和流程图知识
        ↓
执行来源校验、完整性校验、去重和格式清洗
        ↓
输出知识正文及来源元数据
```

每条知识必须至少能够定位到标准文件；条件允许时同时保留标准编号、结构节点编号和节点路径。定位字段用于审计和检索，不拼接成无意义的知识正文。

### 4.1 Neo4j 导出结构解析

节点业务类型取自 `n.properties.label`，不能使用 `n.labels`中的图谱标签代替；节点唯一标识优先使用业务属性 `id`，Neo4j 的 `identity`和 `elementId`只用于本批次关系端点解析。关系从 `p.start`、`p.end`和 `p.type`恢复，端点解析完成后再映射为业务节点类型。`filename`在当前导出中表现为单元素数组，转换时归一为标准来源标识，但不得删除原始数组值。

### 4.2 节点类型归一化

正常情况下以 `properties.label`作为节点类型。当前图谱中存在少量原本承担章节或附录结构作用、却被标记为“引用标准”的节点。这些节点通常具有章节式编号，并作为“规定”“定义”或“包含”关系的起点连接要求、指标、方法或资源。遇到这类对象时，按以下规则处理：

1. 同一文件内，该节点具有章节式编号，并且承担结构节点才可能承担的出边角色时，可在转化上下文中标记为“结构代理节点”。
2. 结构代理只用于恢复知识来源位置和关系上下文，不修改原始图谱数据，也不把它输出为外部引用知识。
3. 仅凭名称类似章节编号不足以改类；缺少关系角色证据时保持原类型并进入复核清单。
4. 术语型结构节点若存在指向自身的“定义”关系，不输出自循环关系知识；该节点内容可按结构原文规则保留。若已有独立术语定义实体，则优先输出术语定义实体。

### 4.3 关系归一化

当前图谱除 schema 中定义的关系外，还存在内部引用直接指向标准结构节点、术语定义或方法节点的情况。转化时先判断关系表达的是文档组织、规范语义还是引用语义：

- “包含”“定义”“规定”主要用于恢复所属结构，不直接生成关系正文；
- 指向同一标准结构节点或术语定义的“引用”按内部引用处理；
- 指向外部标准或公开文件的“引用”按外部引用处理；
- 来源节点和目标节点相同的自循环关系直接过滤；
- 节点类型明显不符合关系角色、且不能按第 4.2 节可靠归一化的关系不进入知识生成，只记录待复核原因；
- 转化前按“起点业务 ID + 关系类型 + 终点业务 ID”去重。当前批次未发现完全重复边，但实现仍应保留该防护。

## 5. 实体属性处理规则

### 5.1 标准文件

标准文件属性用于形成少量文件级档案知识。相近属性必须分组，不允许把每个属性机械转成单独知识。

| 属性组 | 使用属性 | 处理方式 |
| --- | --- | --- |
| 文件身份 | 标准中文名称、标准英文名称、标准编号、标准性质 | 组装一条身份知识 |
| 发布实施 | 发布单位、发布日期、实施日期、标准状态 | 组装一条发布实施知识 |
| 分类信息 | ICS、CCS | 组装一条分类知识，至少一个字段非空时产出 |
| 制修订信息 | 代替标准、首次发布日期、标准主要变化 | 分别按完整语义组装，不合并成长句 |
| 编制信息 | 提出单位、归口单位、起草单位、参与起草单位、主要起草人 | 按机构职责组装为一条编制知识 |
| 范围与目的 | 适用范围摘要、制定背景、制定目的 | 原文结构节点优先，文件属性仅作兜底 |
| 分类标签 | 合规风险类型 | 仅作知识元数据，不进入正文 |

**推荐模板：**

```text
文件身份：{标准中文名称}[（{标准编号}）]是{标准性质}[，英文名称为“{标准英文名称}”]。

发布实施：{标准中文名称}由{发布单位}发布[，发布日期为{发布日期}][，实施日期为{实施日期}][，当前状态为{标准状态}]。

标准分类：{标准中文名称}的国际标准分类号为{ICS}，中国标准文献分类号为{CCS}。

代替关系：{标准中文名称}[（{标准编号}）]代替{代替标准}。

编制信息：{标准中文名称}由{提出单位}提出、由{归口单位}归口，并由{起草单位}负责起草[；参与起草单位包括{参与起草单位}][；主要起草人包括{主要起草人}]。
```

方括号中的字段为空时删除对应片段。模板经删除后若不能形成完整句，则整条跳过。

`制定背景`、`制定目的`和`适用范围摘要`不得与引言节点、范围节点的完整原文重复输出。优先级见第 7 节。

### 5.2 标准依据

标准依据节点不单独产出属性知识，仅通过“标准文件-依据-标准依据”关系形成依据知识。标准编号、标准名称、依据类型、年份和是否注日期用于确定引用对象及组织句子。

**模板：**

```text
{标准文件名称}[（{标准文件编号}）]{依据类型}{标准依据名称或编号}。
```

`依据类型`按原值转为自然表达：采用、代替、引用、依据、参考。值为“其他”时，若无法从原文关系判断具体语义，使用中性表达“涉及”，不得擅自改为“依据”。

### 5.3 标准结构节点

标准结构节点用于恢复条文上下文和补充原文覆盖，不按节点属性逐项生成知识。当前图谱共有 1,530 个标准结构节点，其中 1,352 个具有节点内容；无内容节点不能仅凭标题产出知识。

当前图谱没有独立的“标准附录”业务类型，附录通过 `是否附录节点`、`附录编号`和节点路径保存在标准结构节点中，应直接沿用本节规则。若其他批次仍保留独立“标准附录”节点，则转换前先依据附录编号、标题、路径和所属标准归并到结构节点；同一附录已经存在对应结构节点时不得重复生成知识。附录中的规范要求、指标、方法、表格和图片仍分别按照对应规则转化，不能把整份附录笼统压缩为一条知识。

| 属性 | 处理方式 |
| --- | --- |
| 节点内容 | 满足完整性和去重条件时生成结构节点原文知识 |
| 节点编号、节点标题、节点路径 | 作为知识定位和正文前缀，不单独输出 |
| 节点类型 | 用于过滤目录、封面等节点，不进入正文 |
| 相关图片地址 | 作为附件元数据，不单独输出 |
| 节点层级、完整路径标题、附录字段 | 作为结构控制字段，不单独输出 |

**结构节点原文知识模板：**

```text
{标准文件名称}{节点编号}[“{节点标题}”]规定：{节点内容}
```

结构节点原文知识必须同时满足：

1. `节点内容`非空，且不是只有标题、页码、目录点线或资源链接。
2. 内容能够表达完整说明、规则或事实，不能只是“见图1”“按表2执行”等孤立指向。
3. 内容未被术语定义、标准要求、指标限值、检测方法或表格知识完整覆盖。
4. 目录节点、封面节点默认不产出；前言、引言和参考文献节点仅在内容具有独立事实或明确引用价值时产出。

如果一个结构节点同时包含已抽取的规范要求和未抽取的说明性内容，不直接输出整个节点造成大段重复。实现时应优先使用证据片段或规范实体正文从节点内容中扣除；暂时无法稳定扣除时，可配置为只输出语义实体，不输出该节点原文，并记录“结构原文待补充”。

### 5.4 术语定义

术语定义是天然的完整知识单元。当前 177 个术语定义节点均具有术语编号、中文术语和定义内容，一个有效术语实体产出一条知识。

**正文优先模板：**

```text
{标准文件名称}{术语编号}将“{中文术语}[（{英文术语}）]”定义为：{定义内容}[。{来源说明}]
```

产出条件：

- 中文术语或英文术语至少一个非空；
- 定义内容非空；
- 来源说明只作为定义的补充，不单独产出知识；
- “定义”关系仅用于寻找所属结构节点，不再额外生成一条关系知识。

### 5.5 标准要求

标准要求是国家标准知识库的核心知识源。当前 1,959 个标准要求节点均具有要求内容、要求类型、约束强度、适用对象和行为描述。由于 Schema 已要求 `要求内容`包含适用对象、行为、条件和数值约束中的必要成分，因此**每个有效标准要求只产出一条正文知识，不再额外生成一条结构化拼接知识**。

**正文模板：**

```text
{标准文件名称}{所属节点编号}[“{所属节点标题}”]规定：{要求内容}
```

| 属性 | 处理方式 |
| --- | --- |
| 要求内容 | 知识正文，必填 |
| 要求类型 | 元数据，不单独输出 |
| 约束强度 | 元数据，可用于检索和质量校验 |
| 约束强度原文 | 证据校验字段，不与要求内容重复输出 |
| 适用对象、适用条件、行为描述 | 结构化检索字段，不再拼成第二条知识 |
| 节点展示名称 | 展示与定位字段，不进入正文 |
| 量化特征、量化条件 | 元数据；量化条件已包含在要求内容时不重复追加 |

有效性要求：

- `要求内容`必须非空并能够独立理解；
- 不能仅为“应符合要求”“进行标识”等缺少对象或父句的片段；
- 约束强度为强制、建议或无约束时，`约束强度原文`应存在；
- `量化特征=定量`时，要求内容或量化条件中应存在可核验的数量表达；
- `要求内容`与结构节点内容完全相同时，仅保留标准要求知识。

### 5.6 指标限值

指标限值必须回答“什么对象的什么指标，在什么条件下受到什么数值约束”。当前 190 个指标限值节点均有来源文本，但只有 187 个具有限值。来源文本存在不等于指标语义成立，必须先检查限值，再决定是否产出。通过校验后优先使用 `来源文本`作为知识正文；来源文本缺失但结构字段完整时，才使用模板组装。

**原文模板：**

```text
{标准文件名称}{所属节点编号}规定：{来源文本}
```

**结构化兜底模板：**

```text
[在{测定条件}下，]{适用对象}的{指标名称}{限值}[，单位为{单位}]。
```

兜底产出条件：

- 指标名称和限值必须非空；
- `来源文本`必须实际表达数值、范围、比例、阈值或其他可量化边界，不能只说明某指标需要监测、记录或管理；
- 适用对象缺失时，只能在指标名称本身已经包含对象且句子仍可独立理解时产出；
- 限值已包含单位时不得重复追加单位；
- 表格中的一行若已经形成指标限值实体，指标知识作为检索入口，原表仍作为资源知识保留，但二者通过来源标识进行关联。

当前批次中 3 个没有 `限值`的节点仅表达对若干水质指标安装在线监测装置的要求，不属于指标限值知识。这类节点不按指标输出；其原文若已经形成标准要求或检测方法知识则参与对应类型去重，否则回退到所属结构节点原文。

### 5.7 试验检测方法

当前图谱包含 88 个试验检测方法候选节点，均具有方法名称和方法内容，但节点标签不能替代语义校验。每个通过校验的方法实体产出一条方法知识；`方法内容`优先作为正文，不把方法名称、步骤和引用标准机械拼接成多条知识。

**正文模板：**

```text
{标准文件名称}{所属节点编号}规定的{方法名称}为：{方法内容}
```

**引用式方法兜底模板：**

```text
{标准文件名称}{所属节点编号}规定，{适用对象}应按{引用标准}进行试验、检测或判定。
```

产出条件：

- 方法名称和方法内容至少能够共同说明检测对象及方法；
- 方法内容应明确表达试验、检测、测定、检验、监测或符合性判定动作及其对象、程序或依据；
- 仅有外部标准引用时，适用对象和引用标准应当明确；
- 普通操作步骤、标识方式、查看路径和管理流程不得转为检测方法知识；
- 仅要求“安装监测装置”而未说明如何监测、测定或判定的内容，本质上是设施配置要求，不按试验检测方法输出；
- 操作步骤作为检索或审计字段，已包含在方法内容时不重复追加。

### 5.8 引用标准

当前图谱包含 536 个引用标准节点，实际混合了外部标准、当前标准自身、内部章节、表格或图号等不同对象。引用标准节点不按属性单独产出知识，只有完成对象分类并存在可核验“引用”关系时才生成引用知识。

引用对象名称按以下优先级确定：

1. `标准名称 + 标准编号`；
2. `标准编号`；
3. `标准名称`。

引用对象分类不能只依赖单个标志字段。当前数据中存在“是否本标准自身引用”为“是”、但“是否内部引用”为“否”的记录，也存在内部章节直接连接到标准结构节点的关系。应按以下顺序综合判断：

1. 关系目标是同一文件的标准结构节点或术语定义时，判为内部引用。
2. `是否本标准自身引用=是`，或目标编号与当前标准编号一致时，判为自身或内部引用。
3. 目标仅为章节号、附录号、表号或图号且没有外部标准前缀时，按内部资源引用处理，不表达为“引用某标准”。
4. 目标具有明确外部标准编号、法规名称或公开文件名称时，判为外部引用。
5. 标志字段、目标名称和关系端点互相冲突且无法可靠判断时，不生成引用知识，进入复核清单。

### 5.9 表格

表格是国家标准原文的重要组成，尤其可能承载大量指标限值。当前图谱共有 100 个表格节点，其中 98 个具有表格内容；93 个节点的 `表格内容`与`表格HTML`完全相同。表格不得只用一句模型摘要替代，也不宜在缺少可靠表头继承逻辑时强行逐行拆分为自然语言。

**表格知识格式：**

```text
{标准文件名称}{所属节点编号}中的{表号}[“{表题}”]如下：
{表格内容}
[表格说明：{表格描述}]
```

处理要求：

- `表格内容`非空时优先使用；若其与`表格HTML`相同，只保留一份，不得重复拼接；
- `表格内容`为空时才回退到`表格HTML`。内容为 Markdown 时保留 Markdown，内容为 HTML 时保留清洗后的 HTML，不能删除合并单元格和表注语义；
- 表题、单位、适用条件和表后注应与表格正文一起保留；
- `表格描述`是辅助检索文本，不能替代完整表格内容；
- 当前 2 个同时缺少`表格内容`和`表格HTML`的节点不产出表格知识；表号、表题或描述不能代替表格正文；
- 表格中的指标限值实体与表格知识允许同时存在，前者用于精确检索，后者用于保持表头、条件、单位和表注上下文；
- 同一 `table_id`只产出一次表格知识。

### 5.10 流程图

当前图谱包含 16 个流程图节点，均保存了 Mermaid 内容及描述。流程图仅在内容通过 Mermaid 基础语法校验时产出，普通图片或文字流程说明不得按流程图规则转换。

**模板：**

````text
{标准文件名称}{所属节点编号}中的{流程图编号}[“{流程图标题}”]表示：{流程图描述}

```mermaid
{流程图内容}
```
````

`流程节点摘要`和`流程关系摘要`用于检索或审核，不在正文中再次逐项转写。流程图内容缺失或不是有效 Mermaid 语法时不产出。`流程图语法类型`可能与代码块首行不完全一致，实际语法类型应以`流程图内容`中的声明为准，属性值只作辅助信息。

### 5.11 图片

当前图谱包含 153 个图片节点，均保存图片类型、图片链接和 `image_id`。图片节点不独立生成自然语言知识，因为这些字段只能说明资源存在，不能完整表达图片承载的技术知识。

处理方式：

- 图片链接、标题和类型作为所属结构节点知识的附件元数据；
- 图片优先依据“标准结构节点-包含-图片”关系挂接；缺少关系时，可使用同一结构节点的`相关图片地址`补充，但必须校验文件归属和地址一致性；
- 图片位于表格中时，挂接到对应表格知识；
- 图片中的明确指标、要求或流程必须由抽取阶段形成相应语义实体后才能转为知识；
- OCR 描述、自动图片摘要或文件名不得直接当作标准事实。

## 6. 关系处理规则

| 关系类别 | 接受的归一化三元组 | 知识处理 |
| --- | --- | --- |
| 文档包含 | 标准文件→标准结构节点 | 不单独产出，用于恢复结构上下文 |
| 层级包含 | 标准结构节点→标准结构节点 | 不单独产出，用于恢复节点路径 |
| 资源包含 | 标准结构节点→表格/流程图/图片 | 不单独产出，用于挂接资源 |
| 术语定义 | 标准结构节点→术语定义 | 不额外产出，术语实体已形成知识 |
| 规范规定 | 标准结构节点→标准要求/指标限值/试验检测方法 | 不额外产出，用于恢复知识来源位置 |
| 文件依据 | 标准文件→标准依据 | 产出一条文件级依据知识 |
| 外部引用 | 标准结构节点/标准要求/试验检测方法→引用标准 | 目标确为外部文件时产出引用知识 |
| 内部引用 | 标准结构节点/标准要求/试验检测方法→同一文件结构节点或术语定义 | 目标明确且正文有引用依据时产出内部引用知识 |
| 语义关联 | 标准要求→试验检测方法 | 仅作为关联元数据；双方正文相同或高度重合时不另造关系知识 |

实际边在进入本表前必须完成第 4.2、4.3 节的类型和关系归一化。由结构代理节点发出的“规定”或“包含”关系，可用于恢复上下文；无法归一化的异常三元组不得因为图谱中存在一条边就直接转成自然语言。

### 6.1 外部引用模板

```text
结构节点引用：{标准文件名称}{节点编号}[“{节点标题}”]{引用说明中的引用动作}{引用对象}。

要求引用：{标准文件名称}{要求定位}中的要求引用{引用对象}[，{引用说明}]。

方法引用：{标准文件名称}{方法定位}中的{方法名称}引用{引用对象}[，{引用说明}]。
```

若 `引用说明`本身已经是完整句，优先使用：

```text
{标准文件名称}{来源定位}规定：{引用说明}
```

### 6.2 内部引用模板

```text
{标准文件名称}{来源节点编号}明确引用本标准{目标章节或附录编号}[，引用说明为：{引用说明}]。
```

内部引用目标必须能够解析到本标准结构节点或明确的章节编号。无法解析时保留引用说明并标记待复核，不能虚构目标节点。

### 6.3 引用知识过滤

- “本标准”“见下文”等无法确定目标的泛指，不单独形成引用知识；
- 图号、表号和章节号不得当作外部标准名称；能够解析到同一文件资源或结构节点时，按内部引用处理；
- 同一来源、同一目标、同一引用说明只保留一次；
- `是否内部引用`和`是否本标准自身引用`只作为判定证据之一，不单独进入正文，也不得覆盖关系端点和标准编号提供的相反证据；
- 标准依据与局部引用同时出现时，根据来源位置分别保留，不因目标相同而错误合并。
- 自循环“定义”“引用”等关系直接过滤；关系端点类型异常且不能可靠归一化时不产出知识。

## 7. 原文优先级与去重规则

### 7.1 知识来源优先级

同一原文片段可能同时存在于结构节点和语义实体中，按以下优先级确定主要知识：

```text
标准要求 / 指标限值 / 试验检测方法 / 术语定义
    > 表格或流程图原始内容
    > 标准结构节点原文
    > 标准文件摘要属性
```

高优先级知识已经完整覆盖原文时，低优先级来源不再生成重复正文。

### 7.2 文本归一化

去重比较前进行以下轻量归一化：

- 统一全角、半角空格和连续空白；
- 统一换行但保留段落、列表和表格结构；
- 清除 Markdown 标题符号，不删除条款编号；
- 统一常见标点，不改写数值、单位、公式和标准编号；
- 不对 OCR 疑似错误进行大幅自动纠正。

### 7.3 去重键

建议使用以下组合键：

```text
文件标识 + 知识类型 + 来源节点编号 + 归一化知识正文
```

标准要求、指标限值、试验检测方法等语义实体如来自同一结构位置且正文完全一致，先分别执行语义完整性校验，再只保留一条正文。主知识类型按文本的主要语义角色确定：明确表达数值边界的优先标记为指标限值知识，明确表达验证程序或检测依据的优先标记为试验检测方法知识，其余规范性表达标记为标准要求知识；其他通过校验的语义类型保存在元数据中，不重复输出正文。表格按 `文件标识 + table_id`优先去重；没有 `table_id`时使用所属节点、表号和归一化表格内容。

图谱节点去重和知识正文去重是两个步骤。当前批次没有重复业务 ID、同文件同名节点或完全重复边，但同一原文可能被抽取为不同语义节点，因此仍必须执行跨类型正文去重。

### 7.4 不应合并的情况

- 相同指标名称在不同适用条件、等级或对象下的限值；
- 同一要求在正文与规范性附录中的不同规定；
- 同一外部标准在文件级依据和具体方法中的不同引用；
- 文本相似但标准编号、章节位置或约束强度不同的要求。

## 8. 知识完整性校验

| 知识类型 | 最低完整性要求 |
| --- | --- |
| 文件档案知识 | 标准名称及至少一个有效事实字段 |
| 术语定义知识 | 术语名称 + 定义内容 |
| 标准要求知识 | 完整要求内容，且能够识别对象或继承后的对象语义 |
| 指标限值知识 | 指标名称 + 带比较含义的限值；来源文本实际包含可量化边界；条件和单位按原文保留 |
| 检测方法知识 | 检测对象或目的 + 明确的试验、检测、测定、检验、监测或判定方法，或可核验的引用标准 |
| 结构原文知识 | 有意义的完整原文，不是标题、页码或孤立引用 |
| 表格知识 | 表格内容 + 所属标准；表题、单位和表注尽量完整 |
| 流程图知识 | 有效 Mermaid 内容 + 所属标准和节点位置 |
| 引用知识 | 明确来源 + 可判定为内部或外部的明确目标 + 原文引用依据 |

校验失败的对象不应强行组装知识。原始节点和属性仍可保留在图谱中，并记录未转化原因，供后续补充或人工复核。

## 11. 实现建议与开关

为便于中期指标复现和后续质量优化，建议设置以下开关：

```python
# 始终建议开启：输出标准要求、术语、指标、方法等核心语义知识。
ENABLE_STANDARD_SEMANTIC_KNOWLEDGE = True

# 在生成正文前校验节点是否满足对应语义类型的最低要求。
ENABLE_SEMANTIC_ROLE_VALIDATION = True

# 归一化结构代理节点、内部直接引用和可判定的关系端点异常。
ENABLE_GRAPH_NORMALIZATION = True

# 补充未被语义实体覆盖的结构节点原文，可能增加知识量。
ENABLE_STRUCTURE_TEXT_FALLBACK = True

# 输出原始表格知识，用于保证表格指标和表注不丢失。
ENABLE_TABLE_KNOWLEDGE = True

# 仅对有效 Mermaid 内容输出流程图知识。
ENABLE_FLOWCHART_KNOWLEDGE = True

# 图片只作为附件，不输出“某标准包含某图片”式知识。
ENABLE_IMAGE_AS_STANDALONE_KNOWLEDGE = False
```

`ENABLE_STRUCTURE_TEXT_FALLBACK`开启时必须同时启用去重。若当前图谱缺少可靠证据片段，建议先按结构节点级别判断：节点下已经存在有效术语、要求、指标或方法时，默认不输出整段节点内容；节点没有任何语义子节点时，再使用节点内容兜底。

`ENABLE_SEMANTIC_ROLE_VALIDATION`和`ENABLE_GRAPH_NORMALIZATION`不建议关闭。前者防止无实际限值的指标、非检测语义的方法进入知识库；后者防止误分类节点和异常关系被直接转写。

## 12. 已确定的核心决策

1. **完整要求只输出一条知识。** `要求内容`已承担完整正文，不再用适用对象、行为描述等字段拼装第二条重复知识。
2. **结构节点用于补覆盖。** 节点内容不是一律删除，也不是一律输出，而是补充未被语义实体覆盖的原文。
3. **指标限值先校验再使用原文。** 只有存在实际数值边界的指标才产出；通过校验后，`来源文本`优先于结构字段拼接。
4. **表格必须保留。** 指标实体用于精确检索，完整表格用于保留上下文，两者可以并存但必须建立来源关联。
5. **图片不单独成知识。** 图片地址和标题是资源信息，应作为附件；只有图片中被明确抽取出的要求、指标或流程才能形成知识。
6. **组织关系不当作知识。** “包含、定义、规定”主要用于恢复上下文，不重复产出关系句。
7. **仅保留明确引用。** “依据、引用”可以形成关系知识，但目标和来源必须能够核验。
8. **分类字段只作元数据。** 合规风险类型、要求类型、约束强度和量化特征服务筛选与校验，不单独构成知识。
9. **节点标签不是知识真实性保证。** 指标、方法和引用对象均需通过语义完整性与关系端点校验。
10. **真实图谱先归一化再转写。** 结构代理节点、内部直接引用和自循环关系必须在知识生成前处理。

## 13. 转化规则汇总与示例

下表示例均取自当前国家标准图谱，用于说明规则的实际执行方式。为控制文档篇幅，表格、流程图及较长原文在示例中使用省略号表示；正式转换时必须保留通过校验的完整原文，不能按照示例截断。

| # | 转化规则 | 输入条件与处理方式 | 转化结果示例 |
| ---: | --- | --- | --- |
| 1 | Neo4j 业务类型解析 | 从 `n.properties.label`读取业务类型，`n.labels`仅作为图谱标签；用 `identity`解析本批次关系端点 | 某节点的 `n.labels`为图谱批次标签、`properties.label`为“术语定义”，应按术语定义处理，而不能把图谱批次标签作为知识类型 |
| 2 | 标准文件身份知识 | 标准中文名称必填，标准编号、性质和英文名称按非空字段组装，不逐属性拆分 | `电子电气产品污染控制标识要求（SJ/T 11364—2014）是行业标准，英文名称为“Marking for the restriction of the use of hazardous substances in electrical and electronic product”。` |
| 3 | 标准发布实施知识 | 标准名称与发布单位、发布日期、实施日期、状态分组组装；空字段不进入正文 | `电子电气产品污染控制标识要求由工业和信息化部发布，发布日期为2014年7月9日，实施日期为2015年1月1日，标准状态为废止。` |

| 6 | 结构节点原文知识 | 节点内容完整、不是标题或孤立指向，并且没有被高优先级语义实体完整覆盖时产出 | `污水综合排放标准4.3.1规定：同一排放口排放两种或两种以上不同类别的污水，且每种污水的排放标准又不同时，其混合污水的排放标准按附录A计算。` |

| 19 | 异常关系过滤 | 自循环关系、端点类型不合法且无法归一化的关系不产出知识 | 术语型结构节点指向自身的“定义”关系直接删除；节点正文仍可按术语或结构原文规则处理 |
