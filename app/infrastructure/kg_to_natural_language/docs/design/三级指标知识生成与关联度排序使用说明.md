# 三级指标知识生成与关联度排序使用说明

## 1. 功能概述

`kg_to_natural_language` 提供三个包级函数，用于根据三级风险指标生成候选知识、计算知识与指标描述的关联度，并发布排序后的自然语言知识：

```python
from app.infrastructure.kg_to_natural_language import (
    generate_risk_indicator_knowledge,
    process_risk_indicator_knowledge,
    rank_risk_indicator_knowledge,
)
```

该流程只使用风险指标树、Neo4j、模型HTTP接口和本地文件系统，不访问 MySQL、MinIO或任务数据库。

## 2. 环境变量

阶段二必须通过环境变量配置API Key：

```text
RISK_RELEVANCE_MODEL_API_KEY
```

可选环境变量：

| 环境变量 | 默认值 | 作用 |
| --- | --- | --- |
| `RISK_RELEVANCE_MODEL_NAME` | `qwen3-30b-a3b-instruct-2507` | 评分模型名称 |
| `RISK_RELEVANCE_MODEL_API_URL` | 实验室OpenAI兼容接口 | `chat/completions`地址 |
| `RISK_RELEVANCE_MAX_CONCURRENCY` | `100` | 最大在途模型请求数 |
| `RISK_RELEVANCE_TOTAL_TIMEOUT_SECONDS` | `120` | 单条知识全部尝试的总时限 |
| `RISK_RELEVANCE_MAX_RETRIES` | `2` | 首次请求之外的最大重试次数 |
| `RISK_RELEVANCE_CHECKPOINT_INTERVAL` | `20` | 每完成多少条知识保存一次检查点 |

API Key只在函数调用时从环境变量读取，不写入日志、异常、JSON或TXT。

## 3. 阶段一函数

```python
result = generate_risk_indicator_knowledge("2.3.1.1")
```

阶段一根据风险指标树中的非空“已找到”文件查询五类Neo4j图谱，复用现有分类转换器生成候选知识。

默认输出：

```text
temp/risk/{指标序号}/
├── {映射文件}_{短哈希}.json
└── all.json
```

`all.json`中的评分字段初始为`pending`，阶段一不调用模型。

## 4. 阶段二函数

```python
import asyncio

result = asyncio.run(
    rank_risk_indicator_knowledge(
        "2.3.1.1",
        max_concurrency=100,
        force=False,
    )
)
```

阶段二要求对应阶段一`all.json`已经存在且状态成功。每个模型请求只包含正式指标描述和一条知识，模型返回：

```json
{
  "relevance_score": 0.85,
  "reason": "该知识直接规定了指标关注的合规要求。"
}
```

模型响应通过格式、字段、类型和范围校验后回写对应知识记录。失败记录保留原知识，分数保持`null`并保存脱敏错误摘要。

默认续跑行为：

1. 已成功评分且分数、原因有效的记录不再请求模型。
2. `pending`和`failed`记录继续评分。
3. `force=True`时重新评分全部知识。
4. 运行过程按固定批次原子更新`all.json`检查点。

阶段二完成后，成功记录首先按关联度从高到低排列；关联度相同时，中文知识优先于其他语言知识，同语言条目保持原始顺序。失败记录统一置于成功记录末尾，并同样按中文优先、原始顺序稳定排列。中文优先只用于同分排序，不会使低关联中文知识排到高关联外文知识之前。

## 5. 端到端函数

```python
import asyncio

result = asyncio.run(
    process_risk_indicator_knowledge(
        "2.3.1.1",
        max_concurrency=100,
    )
)
```

端到端函数先在线程中执行阶段一，再异步执行阶段二，返回指标信息、映射文件数、图谱命中数、未命中数、知识数、评分成功数、评分失败数、输出路径和总耗时。

## 6. 最终成果

阶段二完整评分信息保存在：

```text
temp/risk/{指标序号}/all.json
```

排序后的自然语言知识保存在：

```text
data/risk/{指标序号}/all.txt
```

`all.txt`每行只包含一条阶段一生成的原始知识正文，不包含分数、原因、知识ID、来源信息或转换器元数据。

当前发布规则只排序、不按分数删除知识。因此TXT中的知识数量原则上与阶段一去重后的非空知识数量一致，高关联知识位于前部，低关联知识位于后部。

## 7. 主要错误语义

以下问题在发送模型请求前终止：

- 指标序号格式错误；
- 阶段一`all.json`不存在或无法解析；
- 阶段一状态不成功；
- 文件中的指标序号与调用参数不一致；
- 正式指标描述或知识正文缺失；
- 模型API Key未配置；
- 并发数、时限、重试次数或检查点间隔非法。

单条知识的超时、限流、服务端异常和无效响应不会中断其他知识评分。任务结果以`partial_success`报告部分失败，并将失败知识保留在最终排序末尾。
