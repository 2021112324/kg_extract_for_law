# 合规指引知识图谱数据转知识条目规则设计

> 设计依据：合规指引原始数据（分点格式、条款格式）、`information_extraction/law_extract/prompt/schema.py`（条款格式）、`information_extraction/v2/guide_p1/prompt/schema.py`（分点格式）、当前批次 `node.json`/`edge.json` 实际图谱数据及现有知识图谱转知识条目规则。
>
> 核心原则：**以原文中能够独立理解、独立核验的完整规范命题为知识主体，以语义实体为主要入口，以结构节点补充原文覆盖，不把分类标签、定位字段或模型概括单独包装成知识。**
>
> 关键设计原则：**转化规则以"节点类型 + 产出条件"为唯一依据，满足条件即生成知识；不依据图谱类型、抽取 Schema 或原始数据格式决定规则。**

---

## 1. 数据特点与设计目标

合规指引数据按原文组织方式分为两类格式，使用不同的抽取 Schema：

| 数据格式 | 代表文件 | 抽取 Schema | 产出的节点类型 |
| --- | --- | --- | --- |
| 分点格式 | “十四五”系列规划、工作方案（以“一、二、三”分点和“（一）（二）”分点组织） | `guide_p1` | 合规指引文件、指引结构节点、指引知识单元、责任主体、量化目标、引用依据 |
| 条款格式 | 上市公司监管指引、章程指引、内部控制规范（以“第一条、第二条”条款组织） | `law_extract` | 法规文件、法条、条款单元、引用依据、法规依据 |

两种格式的节点类型名称不同，但承担的语义角色一致（文件级、结构级、内容单元、量化目标、责任主体、引用目标）。**转化规则只按语义角色和节点自身属性判断，不区分数据来自哪种格式或哪个 Schema。**

当前批次图谱为分点格式抽取结果，共 10 份“十四五”规划，包含 2,813 个节点、3,832 条关系。节点类型分布如下：

| 节点类型 | 节点数 | 关键字段实际情况 | 转化定位 |
| --- | ---: | --- | --- |
| 合规指引文件 | 10 | 文件全称、文件类型均有值；文号、发布单位、发布日期、适用范围、制定目的部分有值 | 形成文件档案知识 |
| 指引结构节点 | 372 | 304 个具有节点内容，68 个仅标题无内容 | 恢复上下文并补充原文覆盖 |
| 指引知识单元 | 2,012 | 知识内容、行为描述、约束强度均有值；知识类型 24 个缺失 | 核心知识入口 |
| 责任主体 | 232 | 主体名称基本完整，16 个缺责任角色 | 责任分工知识 |
| 量化目标 | 89 | 约束关系全量，最小值 96.6%，原始文本 93.3% | 通过量化完整性校验后产出 |
| 引用依据 | 98 | 文件全称、引用原文基本完整 | 通过引用关系产出 |

条款格式图谱（6 份监管指引、规范类文件）尚未进入本批次，其节点类型（法规文件、法条、条款单元、引用依据、法规依据）与分点格式对应节点遵循同一套条件规则，已在本文档一并纳入。

合规指引知识条目转化需要实现以下目标：

1. 完整保留指引中能够独立核验的政策目标、行动任务、要求、禁止性规定、保障措施、量化目标和责任分工。
2. 避免把文件编号、章节路径、节点类型、风险标签等管理字段单独转成知识。
3. 对未形成独立语义实体的说明性原文，通过指引结构节点内容提供覆盖。
4. 对量化目标和责任主体采用适合其信息形态的处理方式，用于精确检索，不与其来源知识单元正文重复输出。
5. 控制指引知识单元正文、结构节点原文和量化/责任子实体之间的重复。
6. 对实际图谱中的误分类节点、异常关系和缺失字段先归一化或过滤，避免把抽取误差继续转写成自然语言知识。

## 2. 合规指引知识的判定标准

一条合规指引知识应当是某份指引文件在特定结构位置中，对某个对象的政策目标、行动任务、要求、禁止性规定、保障措施、量化目标、责任分工或引用关系所作的**完整、可验证、可复用**表达。

能够作为知识条目的内容主要包括：

- 指引文件明确规定的制定目的、适用范围和文件身份；
- 对政策目标、行动任务、指导性要求、禁止性要求、保障措施的完整命题；
- 带有适用对象、数值边界、单位或条件的量化目标；
- 明确承担牵头、配合、落实、监督等职责的组织主体；
- 指引原文中明确存在的依据、引用关系；
- 无法归入上述语义对象，但本身具有完整含义的结构节点正文。

以下内容不应单独作为知识条目：

- 节点编号、节点路径、节点类型、行号、资源 ID 等结构定位信息；
- 合规风险类型、知识类型、约束强度、责任角色等分类或检索标签；
- 只有标题而没有正文的章节节点；
- 由模型概括但无法回到原文核验的推断性描述；
- “某节点包含某节点”“某章节提出某要求”等纯图谱组织关系；
- 从指引主题推断出的经济行业、合规域或适用场景。

## 3. 知识产出类型

| # | 知识类型 | 主要来源节点 | 产出原则 |
| --- | --- | --- | --- |
| 1 | 文件档案知识 | 合规指引文件 / 法规文件 | 对明确文件信息分组组装，不逐属性输出 |
| 2 | 指引内容知识 | 指引知识单元 / 条款单元 | 知识内容 / 条款单元内容直接作为正文，一个完整命题一条知识 |
| 3 | 量化目标知识 | 量化目标 / 条款单元量化条件 | 通过量化完整性校验后产出，原文优先，结构化字段兜底 |
| 4 | 责任分工知识 | 责任主体 / 条款单元责任角色 | 主体名称 + 责任角色，用于“谁负责”检索 |
| 5 | 结构节点原文知识 | 指引结构节点 | 只补充未被语义实体覆盖的完整原文 |
| 6 | 引用知识 | 引用依据 / 法规依据 | 仅对原文明示的引用/依据关系产出 |
| 7 | 法条效力知识 | 法条 | 效力范围非空时产出 |

## 4. 总体转化流程

```text
读取并解析 Neo4j 导出的节点和关系
        ↓
按 filename 划分单份指引子图
        ↓
归一化节点类型、关系端点和异常关系
        ↓
恢复指引文件、结构节点及语义实体的上下文
        ↓
生成文件档案、指引内容、量化目标、责任分工和引用知识
        ↓
识别已被语义实体覆盖的结构节点原文范围
        ↓
补充未覆盖的结构节点原文知识
        ↓
执行来源校验、完整性校验、去重和格式清洗
        ↓
输出知识正文及来源元数据
```

每条知识必须至少能够定位到指引文件；条件允许时同时保留结构节点编号和节点路径。定位字段用于审计和检索，不拼接成无意义的知识正文。

### 4.1 Neo4j 导出结构解析

节点业务类型取自 `n.properties.label`，不能使用 `n.labels` 中的图谱标签代替；节点唯一标识优先使用业务属性 `id`，Neo4j 的 `identity` 和 `elementId` 只用于本批次关系端点解析。关系从 `p.start`、`p.end` 和 `p.type` 恢复，端点解析完成后再映射为业务节点类型。`filename` 在当前导出中表现为单元素数组，转换时归一为标准来源标识，但不得删除原始数组值。

### 4.2 节点类型归一化

正常情况下以 `properties.label` 作为节点类型。当前图谱存在少量字段缺失和端点异常，转换时按以下规则处理，**不修改原始图谱数据，只调整转化上下文**：

1. `指引知识单元` 中 `知识类型` 为空的节点，不因缺少标签而丢弃；其正文仍按“指引内容知识”产出，`知识类型` 留空并进入复核清单。
2. 端点类型与关系角色不匹配的关系（如“由其负责”指向“引用依据”、“设定目标”指向“量化目标”自身），不进入知识生成，只记录待复核原因。
3. 同一节点若同时出现在多个格式中，按 `label` 实际值处理，不做跨格式重命名；格式差异只体现在属性集合不同，不影响转化规则。

### 4.3 关系归一化

当前图谱除 schema 中定义的关系外，还存在少量端点异常。转化时先判断关系表达的是文档组织、结构归属还是语义关联：

- “包含”“提出”主要用于恢复所属结构和知识来源位置，不直接生成关系正文；
- “引用”用于生成引用知识，目标和来源必须能够核验；
- “由其负责”“设定目标”用于把子实体挂接到其来源知识单元，不单独生成关系句；
- 端点类型与关系角色不符的关系不进入知识生成，只记录待复核原因；
- 转化前按“起点业务 ID + 关系类型 + 终点业务 ID”去重。

## 5. 实体属性处理规则

### 5.1 文件节点（合规指引文件 / 法规文件）

文件节点属性用于形成少量文件级档案知识。相近属性必须分组，不允许把每个属性机械转成单独知识。两种格式的文件节点属性名略有差异，按同一套分组规则处理。

| 属性组 | 分点格式属性 | 条款格式属性 | 处理方式 |
| --- | --- | --- | --- |
| 文件身份 | 文件全称、文件类型、文号 | 文件全称、文件性质、文号 | 组装一条身份知识 |
| 发布实施 | 发布单位、发布日期 | 发布单位、发布日期、生效日期、时效性 | 组装一条发布实施知识 |
| 制定目的 | 制定目的 | 制定目的 | 制定目的非空时单独一条 |
| 适用范围 | 适用范围 | 应用范围 | 适用范围非空时单独一条 |
| 分类标签 | 合规风险类型 | 合规风险类型、合规域、经济行业 | 仅作知识元数据，不进入正文 |

**推荐模板：**

```text
文件身份：{文件全称}[（{文号}）]是[{发布单位}发布的]{文件类型/文件性质}。

发布实施：{文件全称}由{发布单位}发布[，发布日期为{发布日期}][，实施日期为{生效日期}][，当前状态为{时效性}]。

制定目的：{文件全称}的制定目的是{制定目的}。

适用范围：{文件全称}的适用范围是{适用范围/应用范围}。
```

方括号中的字段为空时删除对应片段。模板经删除后若不能形成完整句，则整条跳过。

`制定目的`、`适用范围`不得与结构节点原文重复输出；结构节点原文优先，文件属性只作兜底（见第 7 节）。

### 5.2 内容单元（指引知识单元 / 条款单元）

内容单元是合规指引知识的核心知识源。两种格式下，内容单元的正文字段都已包含完整命题，**每个有效内容单元只产出一条正文知识，不再用适用对象、行为描述等结构化字段拼装第二条重复知识**。

| 属性 | 分点格式（指引知识单元） | 条款格式（条款单元） | 处理方式 |
| --- | --- | --- | --- |
| 正文 | 知识内容（100%） | 条款单元内容（100%） | 知识正文，必填 |
| 知识类型 | 知识类型（98.8%） | 功能类型 | 元数据，不单独输出 |
| 约束强度 | 约束强度（99.9%） | — | 元数据，可用于检索和质量校验 |
| 适用对象/主体 | 适用对象（96.3%） | 适用主体 | 元数据，不再拼第二条知识 |
| 行为描述 | 行为描述（100%） | 行为描述 | 元数据 |
| 适用条件/前提 | 适用条件（18.0%） | 适用前提 | 元数据 |
| 时间要求/限制 | 时间要求（6.8%） | 时间限制 | 元数据 |
| 例外/后果 | — | 例外情形、法律后果 | 元数据；已含于正文时不再重复 |
| 原文依据 | 原文依据（96.4%） | — | 证据校验字段，不与正文重复输出 |
| 候选标志 | 是否知识条目候选（100%） | — | 为 false 时不产出 |

**正文模板：**

```text
{文件全称}{结构节点编号}[“{结构节点标题}”]{提出/规定}：{知识内容/条款单元内容}
```

**产出条件：**

- 正文（知识内容 / 条款单元内容）非空，并能够独立理解；
- 不能仅为“加强管理”“做好工作”等缺少对象或行为主体的空洞表述；
- `是否知识条目候选` 为 false 时不产出（分点格式）；
- `知识类型` 为空不影响产出，仅记录待复核；
- 正文与来源结构节点内容完全相同时，仅保留内容单元知识。

### 5.3 结构节点（指引结构节点）

指引结构节点用于恢复条文上下文和补充原文覆盖，不按节点属性逐项生成知识。当前图谱共有 372 个结构节点，其中 304 个具有节点内容；无内容节点不能仅凭标题产出知识。

| 属性 | 处理方式 |
| --- | --- |
| 节点内容 | 满足完整性和去重条件时生成结构节点原文知识 |
| 节点标题、显示编号、完整路径 | 作为知识定位和正文前缀，不单独输出 |
| 结构类型（一级标题/二级分点/专栏/编号分点/章） | 用于过滤目录、封面等节点，不进入正文 |
| 起始行、结束行、顺序 | 作为结构控制字段，不单独输出 |

**结构节点原文知识模板：**

```text
{文件全称}{显示编号}[“{节点标题}”]提出：{节点内容}
```

结构节点原文知识必须同时满足：

1. `节点内容` 非空，且不是只有标题、页码或目录点线。
2. 内容能够表达完整说明、规则或事实，不能只是“见下文”“如图 1 所示”等孤立指向。
3. 内容未被指引知识单元、量化目标或责任分工知识完整覆盖。
4. 一级标题、章等纯标题节点默认不产出；专栏节点仅在内容具有独立事实时产出。

### 5.4 条文节点（法条）

条文节点仅存在于条款格式图谱中，对应“条”层级。其效力范围是唯一能够独立成文的属性。

| 属性 | 处理方式 |
| --- | --- |
| 效力范围 | 非空时生成法条效力知识 |
| 核心主题 | 摘要标签，不单独输出 |
| 适用行业、合规域、经济行业 | 分类标签，不单独输出 |

**法条效力知识模板：**

```text
{文件全称}{法条标识}的效力范围是{效力范围}
```

### 5.5 量化目标（量化目标 / 条款单元量化条件）

量化目标必须回答“什么对象在什么条件下受到什么数值约束”。当前 89 个量化目标节点均有约束关系，86 个具有最小值，83 个具有原始文本。来源文本存在不等于量化语义成立，必须先检查数值，再决定是否产出。通过校验后优先使用 `原始文本` 作为知识正文；原始文本缺失但结构字段完整时，才使用模板组装。

**原文模板：**

```text
{文件全称}{所属节点编号}提出：{原始文本}
```

**结构化兜底模板：**

```text
[在{适用条件}下，]{适用条件}达到{约束关系表达}{最小值}[～{最大值}]{单位}。
```

兜底产出条件：

- `最小值` 或 `最大值` 至少一个非空；
- `约束关系` 非空（等于、下限、上限、区间、约数等）；
- `原始文本` 缺失时，`适用条件` 必须非空且能独立理解；
- 单位已包含在适用条件或原始文本中时不得重复追加单位；
- 同一量化目标只产出一条知识。

`量化值类型`、`最小值`、`最大值`、`单位`、`约束关系` 均为结构化检索字段，不单独拼成第二条知识。条款格式中量化信息以 `条款单元.量化条件`（结构化对象）形式存在，提取 `原文件` 字段作为可读文本，按同一套规则处理。

### 5.6 责任主体（责任主体 / 条款单元责任角色）

责任主体回答“某项任务由谁承担什么责任”。当前 232 个责任主体节点中，227 个具有主体名称，216 个具有责任角色。

| 属性 | 处理方式 |
| --- | --- |
| 主体名称 | 知识正文主体，非空时产出 |
| 责任角色（牵头/配合/落实/监督/其他明确责任） | 元数据，用于检索，可补充到正文 |
| 责任原文 | 证据校验字段，不与正文重复输出 |

**责任分工知识模板：**

```text
{文件全称}{所属节点编号}明确，{主体名称}[承担{责任角色}责任]。
```

产出条件：

- `主体名称` 非空；
- `责任角色` 为空时仍可产出，但只在主体名称能够独立表达责任分工时（如主体名称已含“按职责分工负责”）；
- 主体名称仅为一个笼统主体且责任角色为空时，进入复核清单，不强行产出。

### 5.7 引用依据（引用依据 / 法规依据）

引用依据是引用目标节点，不按属性单独产出知识，只有存在可核验的“引用/依据”关系时才生成引用知识（见第 6 节）。

| 属性 | 处理方式 |
| --- | --- |
| 文件全称 | 用于确定引用对象，非空时有效 |
| 文件别名 | 引用对象简称，可选补充 |
| 引用原文 / 责任原文 | 证据校验字段 |
| 条款编号、引用类型、引用关系、引用目的 | 条款格式专有，用于确定引用方式和组装句子 |

## 6. 关系处理规则

| 关系类别 | 接受的归一化三元组 | 知识处理 |
| --- | --- | --- |
| 文件包含 | 合规指引文件 → 指引结构节点 | 不单独产出，用于恢复结构上下文 |
| 层级包含 | 指引结构节点 → 指引结构节点 | 不单独产出，用于恢复节点路径 |
| 结构提出 | 指引结构节点 → 指引知识单元 | 不额外产出，用于恢复知识来源位置 |
| 责任归属 | 指引知识单元 → 责任主体 | 责任主体已形成责任分工知识，不额外产出关系句 |
| 目标设定 | 指引知识单元 → 量化目标 | 量化目标已形成量化目标知识，不额外产出关系句 |
| 文件依据 | 法规文件 → 法规依据 | 产出一条文件级引用知识 |
| 内容引用 | 指引知识单元 / 条款单元 → 引用依据 | 目标明确且原文有引用依据时产出引用知识 |

实际边在进入本表前必须完成第 4.2、4.3 节的类型和关系归一化。由结构节点发出的“提出”或“包含”关系，可用于恢复上下文；无法归一化的异常三元组不得因为图谱中存在一条边就直接转成自然语言。

### 6.1 引用知识模板

**文件级引用（合规指引文件 / 法规文件 → 引用依据 / 法规依据）：**

```text
{文件全称}依据{引用对象全称}[（{文件别名}）]制定。
```

**内容级引用（指引知识单元 / 条款单元 → 引用依据）：**

```text
{文件全称}{所属节点编号}中的{内容定位}引用{引用对象全称}[（{文件别名}）]。
```

若 `引用原文` 本身已经是完整句，优先使用：

```text
{文件全称}{来源定位}规定：{引用原文}
```

### 6.2 引用知识过滤

- “本指引”“本规范”“见下文”等无法确定目标的泛指，不单独形成引用知识；
- 目标为章节号、表号或图号而非公开文件时，不按外部引用处理；
- 同一来源、同一目标、同一引用说明只保留一次；
- 文件别名只作为引用对象的补充，不单独进入正文。

## 7. 原文优先级与去重规则

### 7.1 知识来源优先级

同一原文片段可能同时存在于内容单元和结构节点中，按以下优先级确定主要知识：

```text
指引知识单元 / 条款单元（内容知识）
    > 量化目标 / 责任分工（子实体精确检索）
    > 指引结构节点原文
    > 文件属性摘要
```

量化目标和责任分工属于子实体语义说明，用于精确检索，不参与正文覆盖优先级判断；其与内容单元正文重复时，按语义去重规则处理。高优先级知识已经完整覆盖原文时，低优先级来源不再生成重复正文。

### 7.2 文本归一化

去重比较前进行以下轻量归一化：

- 统一全角、半角空格和连续空白；
- 统一换行并保留段落、列表结构；
- 清除 Markdown 标题符号，不删除条款编号；
- 统一常见标点，不改写数值、单位、公式和文件编号；
- 不对 OCR 疑似错误进行大幅自动纠正。

### 7.3 去重键

建议使用以下组合键：

```text
文件标识 + 知识类型 + 来源节点编号 + 归一化知识正文
```

内容单元、量化目标、责任分工等语义实体如来自同一结构位置且正文完全一致，先分别执行语义完整性校验，再只保留一条正文。主知识类型按文本的主要语义角色确定：明确表达数值边界的优先标记为量化目标知识，明确表达主体职责的优先标记为责任分工知识，其余规范性表达标记为指引内容知识；其他通过校验的语义类型保存在元数据中，不重复输出正文。

图谱节点去重和知识正文去重是两个步骤。同一原文可能被抽取为不同语义节点，因此仍必须执行跨类型正文去重。

### 7.4 不应合并的情况

- 相同指标名称在不同适用条件、对象或阶段下的量化目标；
- 同一责任主体在不同知识单元中承担的不同角色；
- 同一外部文件在文件级依据和具体内容引用中的不同引用；
- 文本相似但来源位置、约束强度或知识类型不同的内容单元。

## 8. 知识完整性校验

| 知识类型 | 最低完整性要求 |
| --- | --- |
| 文件档案知识 | 文件全称及至少一个有效事实字段 |
| 指引内容知识 | 完整内容正文，且能够识别对象或行为主体 |
| 量化目标知识 | 最小值或最大值非空 + 约束关系非空；原始文本实际包含可量化边界 |
| 责任分工知识 | 主体名称非空；责任角色或主体名称能够独立表达责任分工 |
| 结构原文知识 | 有意义的完整原文，不是标题、页码或孤立引用 |
| 引用知识 | 明确来源 + 可判定目标 + 原文引用依据 |
| 法条效力知识 | 法条标识 + 效力范围非空 |

校验失败的对象不应强行组装知识。原始节点和属性仍可保留在图谱中，并记录未转化原因，供后续补充或人工复核。

## 9. 推荐输出结构

知识正文可以继续输出为每行一条的 TXT，同时建议保留可审计的 JSONL 或 JSON 数据。推荐最小结构如下：

```json
{
  "knowledge_id": "稳定知识ID",
  "knowledge_type": "指引内容知识",
  "semantic_types": ["指引内容知识"],
  "content": "“十四五”国家知识产权保护和运用规划明确：……",
  "source_file": "原始文件名",
  "guide_name": "文件全称",
  "source_node_id": "来源图谱节点ID",
  "source_node_type": "指引知识单元",
  "source_location": "三/（一）/1",
  "risk_types": ["产品法律风险"],
  "attachments": [],
  "metadata": {
    "knowledge_type": "行动任务",
    "constraint_strength": "强制任务"
  }
}
```

其中 `content` 是实际知识正文；来源、分类和定位信息均为元数据，不应与正文混写。TXT 输出只写 `content`，JSON 输出保留完整审计字段。

## 10. 实现建议与开关

为便于中期指标复现和后续质量优化，建议设置以下开关：

```python
# 始终建议开启：输出指引内容、量化目标、责任分工等核心语义知识。
ENABLE_GUIDE_SEMANTIC_KNOWLEDGE = True

# 在生成正文前校验节点是否满足对应语义类型的最低要求。
ENABLE_SEMANTIC_ROLE_VALIDATION = True

# 归一化结构节点、端点异常和可判定的关系端点问题。
ENABLE_GRAPH_NORMALIZATION = True

# 补充未被语义实体覆盖的结构节点原文，可能增加知识量。
ENABLE_STRUCTURE_TEXT_FALLBACK = True

# 是否输出量化目标知识（子实体精确检索）。
ENABLE_QUANTITATIVE_TARGET_KNOWLEDGE = True

# 是否输出责任分工知识（子实体精确检索）。
ENABLE_RESPONSIBILITY_KNOWLEDGE = True
```

`ENABLE_STRUCTURE_TEXT_FALLBACK` 开启时必须同时启用去重。若当前图谱缺少可靠证据片段，建议先按结构节点级别判断：节点下已经存在有效内容单元时，默认不输出整段节点内容；节点没有任何语义子节点时，再使用节点内容兜底。

`ENABLE_SEMANTIC_ROLE_VALIDATION` 和 `ENABLE_GRAPH_NORMALIZATION` 不建议关闭。前者防止无实际数值边界的量化目标、非完整命题的内容单元进入知识库；后者防止误分类节点和异常关系被直接转写。

## 11. 已确定的核心决策

1. **规则以节点类型 + 条件为依据。** 满足条件即生成知识，不依据图谱类型、抽取 Schema 或数据格式决定规则。
2. **完整命题只输出一条知识。** 内容单元的 `知识内容`/`条款单元内容` 已承担完整正文，不再用适用对象、行为描述等字段拼装第二条重复知识。
3. **结构节点用于补覆盖。** 节点内容不是一律删除，也不是一律输出，而是补充未被语义实体覆盖的原文。
4. **量化目标先校验再使用原文。** 只有存在实际数值边界的量化目标才产出；通过校验后，`原始文本` 优先于结构字段拼接。
5. **责任主体用于精确检索。** 主体名称 + 责任角色回答“谁负责”，不与其来源内容单元正文重复。
6. **组织关系不当作知识。** “包含、提出、由其负责、设定目标”主要用于恢复上下文，不重复产出关系句。
7. **仅保留明确引用。** “引用、依据”可以形成引用知识，但目标和来源必须能够核验。
8. **分类字段只作元数据。** 合规风险类型、知识类型、约束强度、责任角色、量化值类型服务筛选与校验，不单独构成知识。
9. **节点标签不是知识真实性保证。** 量化目标、责任主体和引用对象均需通过语义完整性与关系端点校验。
10. **真实图谱先归一化再转写。** 端点异常、缺失字段和异常关系必须在知识生成前处理。
