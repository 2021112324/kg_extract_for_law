# 风险指标知识条目数统计实施与测试报告

## 1. 实施范围

本次新增 `build_risk_indicator_knowledge_statistics()` 公共函数，根据风险指标映射树和 `temp/risk` 下的阶段一 `all.json`，生成三级指标以及风险根、一级、二级层次的知识条目数统计。默认结果以 JSON 保存到 `data/stats/知识条目数统计.json`。

统计过程只读取本地 JSON，不查询 Neo4j、不调用大模型，也不依赖 MySQL 或 MinIO。原有知识生成、关联度评分、排序和全量断点续跑接口未改变。

## 2. 统计口径

三级指标以自身阶段一成果中的实际唯一知识标识计数，不直接采用未经校验的声明数量。父级统计以规范化来源文件为去重单位：同一文件被多个后代三级指标映射时，在同一父级只合并统计一次；不同六类风险根节点分别执行去重。

风险树中的全部三级指标都会出现在统计树中。阶段一成果不存在、无法解析或指标身份不一致时，分别标记为缺失或无效，并使对应父级保持不完整状态。同一文件在多个指标中的知识集合不一致时，使用集合并集避免漏计，同时记录冲突。

## 3. 自动化测试

新增测试覆盖以下内容：

- 风险树一次加载、六类风险根节点、四段指标序号和数字顺序；
- 重复序号、缺失描述、非法成果和指标身份不一致；
- 三级指标实际知识计数及声明数量不一致；
- 同一文件在二级、一级和风险根节点中的去重；
- 不同风险根节点独立统计；
- 文件名路径、扩展名、空白和大小写归一；
- 缺失来源文件、历史知识标识兼容和跨图谱类别冲突；
- 冲突集合并集、输出顺序稳定、默认及自定义路径；
- JSON 原子写入失败时不保留半写文件。

新增和指标树相关测试共 12 项，全部通过。风险生成、评分排序、图谱查询、转换器及包级接口回归测试共通过 61 项。另有 2 项既有五类批处理测试因合规指引测试图谱存在节点但测试转换结果为空而失败，其调用链未进入本次新增统计模块，已作为现有测试夹具与转换规则之间的独立问题保留。

## 4. 真实数据验证

使用当前正式风险映射树和 `temp/risk` 执行统计，成功生成 JSON。校验结果如下：

- 风险根节点、一级、二级、三级层次分别识别为 6、41、113、183；
- 当前 47 个三级指标存在合法阶段一成果，136 个尚无阶段一成果，无无效成果；
- 所有可用三级指标的统计数量均与其 `all.json` 中实际唯一知识数量一致；
- 当前有 89 个规范化文件被多个三级指标复用；
- 11 个二级指标的父级去重数量小于子指标直接相加数量，证明重复文件未被重复统计；
- 未发现同一文件知识集合不一致或跨图谱类别冲突；
- 未触发声明数量不一致、缺失来源或历史知识标识兼容警告。

由于仍有三级指标尚未生成阶段一成果，本次统计状态为 `partial_success`。该状态反映数据覆盖进度，不表示已生成成果存在统计错误。

## 5. 产物与使用

默认统计文件：

```text
app/infrastructure/kg_to_natural_language/data/stats/知识条目数统计.json
```

调用方式：

```python
from app.infrastructure.kg_to_natural_language import (
    build_risk_indicator_knowledge_statistics,
)

result = build_risk_indicator_knowledge_statistics()
```

阶段一成果发生变化后，需要重新调用该函数刷新统计快照。调用方应结合 `status`、覆盖数量和 `is_complete` 判断统计是否覆盖全部三级指标，不能把缺失成果解释为零知识。
