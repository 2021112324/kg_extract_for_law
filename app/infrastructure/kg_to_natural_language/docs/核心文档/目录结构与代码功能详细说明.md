# `kg_to_natural_language` 目录结构与代码功能详细说明

本文档依据 `app/infrastructure/kg_to_natural_language` 当前代码和目录结构编写，说明各目录的职责、各 Python 文件的功能、主要调用关系及运行数据的组织方式。

说明范围包括该模块内部的代码、配置资源、文档、临时产物和正式产物。按三级指标生成的大量同构目录以 `<三级指标序号>` 统一表示，不逐一重复列举。

## 第一章 目录结构与功能概览

### 1.1 模块总体职责

`kg_to_natural_language` 负责把 Neo4j 中的结构化知识图谱转换为可检索、可汇总的自然语言知识条目，并进一步支持按三级风险指标汇集、评分、排序和统计知识。模块主要包含五条业务链路：

1. Neo4j 图谱导出为 `node.json` 和 `edge.json`。
2. 按中文法规、国家标准、英文法规和合规指引规则生成自然语言知识。
3. 按五类固定图谱标签批量生成正式分类知识库。
4. 按三级风险指标查找映射文件知识，调用大模型评分并发布排序结果。
5. 基于指标树和阶段一成果，按三级及上级风险层次统计知识数量，并在父级范围内消除重复文件造成的重复计数。

其中，`risk/tree/risk2file_tree.json` 是风险指标知识处理链路的核心配置数据。该文件把六类风险下的三级指标、指标描述、外部合规依据及实际找到的图谱文件连接起来，决定每个三级指标需要从哪些文件中生成知识。没有该映射树，系统只能按图谱类别生成知识，不能形成“三级指标到映射文件知识”的风险视图。

模块只使用 Neo4j、本地文件系统和风险评分模型接口，不依赖 MySQL 或 MinIO。

### 1.5 核心映射文件 `risk/tree/risk2file_tree.json`

`risk2file_tree.json` 不是运行日志或可删除的临时产物，而是风险指标知识生成所依赖的核心输入配置。其作用是把风险指标体系与已经进入 Neo4j 的法规、标准、监管规则、英文法规和合规指引文件建立联系。

该文件按以下逻辑组织：

```text
六类风险根节点
└── 三级指标名称
    ├── 序号
    ├── 指标描述
    └── 映射文件
        └── 地区或文件类型
            └── 具体映射文件
                ├── 原始文本
                └── 已找到
```

其中各部分承担不同作用：

- 六类风险根节点用于统一风险分类口径；
- 三级指标名称和序号用于确定最终 `data/risk/<三级指标序号>` 目录；
- 指标描述是大模型判断知识与指标关联度的评分依据；
- 映射文件记录指标对应的外部合规依据；
- `原始文本` 保留映射表中的原始文件表述；
- `已找到` 保存已经爬取、解析并进入知识图谱的实际文件名，是后续查询 Neo4j 的直接依据。

风险知识阶段一读取该文件后，只处理 `已找到` 非空的映射文件，并在“法律法规条款、国家标准、行政监管规则、英文法规、合规指引”五类图谱中查找对应文件子图。命中的图谱数据转换并汇总到 `temp/risk/<三级指标序号>/all.json`，随后经过关联度评分和排序，发布为 `data/risk/<三级指标序号>/all.txt`。

因此，该文件直接决定以下结果：

1. 系统能够处理哪些三级指标；
2. 每个指标采用哪些外部依据文件；
3. 哪些映射文件因尚未找到而暂不参与知识生成；
4. 每个指标生成知识的来源范围；
5. 评分时使用哪一段指标描述。

修改 `risk2file_tree.json` 后，已有 `data/risk` 成果不会自动更新。若三级指标描述、映射文件或 `已找到` 值发生变化，需要重新执行对应指标；若希望覆盖已有非空最终成果，应显式使用强制重跑方式。修改前还应校验六类风险根节点、三级指标序号唯一性、指标描述完整性和映射文件结构，避免错误配置影响整批风险知识。

## 第二章 根目录入口代码

### 2.1 `__init__.py`

该文件是模块的统一公共入口，主要承担三项职责。

第一，导入并重新暴露内部功能。调用方可以直接使用：

```python
from app.infrastructure.kg_to_natural_language import process_graph
```

而不必从 `graph.exporter`、`converters.router` 或 `risk.ranking` 等内部模块导入。

第二，提供三个包级编排函数：

- `process_graphs_by_type()`：处理五类固定标签，成果发布到 `data/type`；
- `process_graph(tag, graph_type)`：导出任意指定标签，并自动识别图谱类型后转换；
- `process_graph_v2(tag, graph_type)`：导出指定标签后固定使用中文法规 v2 转换器。

第三，注册旧模块名兼容别名。目录重组前的导入路径仍可继续使用，为已有调用方迁移到新目录结构提供过渡。

该文件的公开接口、参数和产物已在同目录核心文档《`__init__.py` 接口功能详细说明》中逐项说明。

## 第三章 `batch` 五类批处理目录

### 3.1 目录职责

`batch` 将“固定知识类别配置”和“批量执行逻辑”分离。它不负责设计具体知识转化规则，而是为每个类别选择已有转换器，并保证五类成果一致发布。

### 3.2 `batch/__init__.py`

该文件是批处理子包入口，导出：

- `TypedKnowledgeCategory`；
- `TYPED_KNOWLEDGE_CATEGORIES`；
- `ALLOWED_TYPED_GRAPH_LABELS`。

它不执行图谱查询和文件写入，只负责稳定内部导入路径。

### 3.3 `batch/categories.py`

该文件使用只读数据类 `TypedKnowledgeCategory` 描述一个知识类别，字段包括：

- 类别名称；
- Neo4j 标签；
- 转换器标识；
- 正式输出文件名。

固定注册的五类知识为：

| 类别 | Neo4j 标签 | 转换器 |
| --- | --- | --- |
| 法律法规条款 | `法律法规条款` | 中文法规转换器 |
| 国家标准 | `国家标准` | 国家标准转换器 |
| 行政监管规则 | `行政监管规则` | 中文法规转换器 |
| 英文法规 | `英文法规` | 英文法规转换器 |
| 合规指引 | `合规指引` | 合规指引转换器 |

该注册表同时供图谱批处理和风险映射文件查询使用，保证两条链路采用一致的类别范围和转换器路由。

### 3.4 `batch/processor.py`

该文件实现 `process_typed_knowledge_entries()`，负责五类图谱的完整批处理。

主要流程如下：

1. 为本次运行创建独立暂存目录。
2. 按类别调用 `export_graph_to_directory()` 导出内部子图。
3. 根据 `categories.py` 的转换器标识选择专用转换器。
4. 校验转换器声明的知识数量与 TXT 非空行数是否一致。
5. 图谱有节点但没有知识时中止发布。
6. 汇总节点、关系、来源文件和知识条目数量。
7. 五类全部成功后，将五个 TXT 和统计 JSON 一次性发布到 `data/type`。
8. 发布失败时恢复上一次完整成果。

文件使用线程锁避免同一进程内重复执行，并通过暂存、备份和 `os.replace` 降低成果只更新一部分的风险。异常使用 `TypedKnowledgeExportError` 标记失败阶段和具体类别。

## 第四章 `converters` 知识转换目录

### 4.1 目录职责

`converters` 是图谱到自然语言知识转换的核心。所有转换器都接收包含 `node.json` 和 `edge.json` 的目录，但会根据知识对象差异采用不同规则。

转换结果分为三类：

- TXT：每行一条最终自然语言知识；
- JSONL：逐条保存知识正文及来源元数据；
- CSV：保存数量、跳过原因和关系问题等统计。

### 4.2 `converters/__init__.py`

该文件集中导出通用转换器、四类专用转换器和自动路由函数。它自身不包含转换规则，作用是提供简洁稳定的子包入口。

### 4.3 `converters/base.py`

`base.py` 同时承担公共工具和旧版通用转换器两类职责。

公共工具包括：

- 判断空值并把复杂属性转换为文本；
- 清理 Windows 文件名中的非法字符；
- 读取并校验 JSON 数组；
- 从 Neo4j 包装记录中提取节点和关系；
- 按 `identity` 和 `elementId` 建立节点索引；
- 解析关系两端节点及来源文件；
- 清理图谱基础属性。

通用转换器包括节点属性句、组合属性句和关系句等基础规则，主要用于兼容旧流程。主入口 `convert_json_to_text()` 输出 TXT 和 `知识条目统计.csv`。中文法规新流程通常使用 `chinese_law.py`，而专门类别使用各自转换器。

### 4.4 `converters/chinese_law.py`

该文件是中文法律法规和行政监管规则的主要转换器，入口为 `convert_json_to_text_v2()`。

转换顺序体现“核心知识优先、补充信息靠后”的原则：

1. 生成法规文件层面的档案知识。
2. 生成条款单元正文和规范要素知识。
3. 根据关系生成引用依据知识。
4. 最后生成法条正文或效力范围等补充知识。

文件中的主要功能组包括：

- `parse_quantification()`：把量化条件转换为可展示文本；
- `build_regulation_source_names()`：建立文件来源名称索引；
- `convert_regulation_documents()`：处理法规文件节点；
- `convert_clause_units()`：处理条款单元及条款定位；
- `convert_references()`：处理法规依据和引用关系；
- `convert_law_articles()`：处理法条层知识；
- `write_txt()`、`write_csv()`：写出知识及统计。

转换器会补充规范文件前缀和条款序号，避免知识脱离来源；同时记录来源语境缺失问题。当前结构化规则开关默认关闭，主流程以稳定的正文及字段组装规则为主。

### 4.5 `converters/national_standard.py`

该文件是国家标准专用转换器，入口为 `convert_national_standard_json_to_text()`。

内部首先把原始导出数据归一为：

- `NodeInfo`：统一后的节点；
- `ResolvedEdge`：已解析起止节点的关系；
- `KnowledgeEntry`：带来源和类型的知识条目；
- `ConversionStats`：跳过、关系和来源语境统计；
- `StandardGraphContext`：节点、关系、层级和来源索引。

之后按标准文件、术语定义、标准要求、指标限值、试验检测方法、结构节点文字、表格描述、流程图描述和有效引用等类别生成候选知识，再进行语义角色校验、去重和稳定编号。

该转换器不会把图片作为独立知识，也不会把原始表格正文、HTML 或 Mermaid 代码写入最终知识。只有存在有效文字描述时，表格和流程图信息才可能形成知识条目。

输出包括 TXT、可审计 JSONL 和统计 CSV。JSONL 中保留知识类型、来源文件、标准名称、标准编号、来源节点、位置、风险类型和其他元数据。

### 4.6 `converters/english_law.py`

该文件是英文法规专用转换器，入口为 `convert_english_law_json_to_text()`，最终知识正文保持英文。

主要特点如下：

1. 支持英文法规文件、法律依据、法条、条款、最小正文单元和引用节点。
2. 从三个英文法规抽取 Schema 模块动态提取允许属性，形成字段白名单。
3. 对确定性切分器产生但未直接声明在 Schema 中的基础字段设置补充白名单。
4. 校验允许的关系三元组和六类风险值。
5. 区分内部引用、未解析引用和可形成知识的外部引用。
6. 在不同正文层级之间执行优先选择和去重，减少相同文本重复输出。
7. 使用英文来源前缀补足知识语境。

内部数据对象包括 `NodeInfo`、`ResolvedEdge`、`KnowledgeEntry`、`ConversionStats` 和 `EnglishLawGraphContext`。输出为英文 TXT、JSONL 和英文表头统计 CSV，并记录候选正文层级、最终正文层级、过滤字段和校验问题。

### 4.7 `converters/compliance_guide.py`

该文件是合规指引专用转换器，入口为 `convert_compliance_guide_json_to_text()`。

转换规则按节点语义而不是文件版式决定，因此能够兼容分点格式指引和部分条款格式指引。主要知识类型包括：

- 文件档案知识；
- 指引内容知识；
- 量化目标知识；
- 责任分工知识；
- 有效结构节点原文知识；
- 引用知识；
- 法条补充知识。

内部使用 `GuideGraphContext` 恢复文件、结构节点、知识单元、责任主体和量化目标之间的上下文。组织关系主要用于恢复语境，不直接机械生成关系句。候选知识经过语义角色校验、来源补充、优先级去重后，输出 TXT、JSONL 和统计 CSV。

### 4.8 `converters/router.py`

该文件负责自动识别图谱类型并分发转换任务。

`detect_graph_type()` 抽样前 200 个节点，读取 `properties.label`，识别：

- 中文法规；
- 国家标准；
- 英文法规；
- 合规指引。

`convert_graph_to_text()` 根据识别结果调用对应专用转换器。若节点为空或类型不在支持范围内，则抛出异常，不使用不确定的默认转换器。

### 4.9 `converters/source_context.py`

该文件解决自然语言知识缺少来源前缀的问题。

- `clean_source_name()`：去除路径、常见扩展名、书名号和无效来源占位词；
- `add_chinese_source_context()`：为中文知识添加规范文件名和可用的条款定位；
- `add_english_source_context()`：为英文知识添加 `Under <document>,` 来源前缀。

函数会检查知识是否已经包含对应前缀，避免重复添加；当来源名称不可用时保留原知识，或仅使用可用的位置描述。

## 第五章 `graph` 图谱导出目录

### 5.1 `graph/__init__.py`

该文件导出 `clear_temp_dir`、`export_graph` 和 `export_graph_to_directory`，作为图谱导出子包的稳定入口。

### 5.2 `graph/exporter.py`

该文件通过项目统一配置连接 Neo4j，将节点和关系转换为与 Neo4j 导出格式一致的 JSON 对象。

主要功能包括：

- 创建和关闭 Neo4j Driver；
- 校验数据库连通性；
- 将 Neo4j 节点和关系转换为可序列化字典；
- 清理 `temp/json`、`temp/txt` 和 `temp/csv`；
- 导出指定标签的节点及关系；
- 返回节点数、关系数和文件路径。

`export_graph()` 接受任意具体图谱标签，写入默认 `temp/json`；`export_graph_to_directory()` 仅接受五类注册标签，写入指定目录，并只保留起止节点都属于当前类别的内部关系。

## 第六章 `risk` 风险指标知识目录

### 6.1 目录职责

`risk` 把指标文件映射树、五类知识图谱和大模型评分连接起来。其输入是三级指标序号，最终输出是该指标对应的、按关联度排序的知识条目集合。

### 6.2 `risk/__init__.py`

该文件声明风险子包用途并导出风险知识统计函数；面向业务调用的完整公共接口仍由上级 `kg_to_natural_language/__init__.py` 统一提供。

### 6.3 `risk/config.py`

该文件集中管理风险知识处理配置：

- 默认指标树路径；
- 阶段一临时成果根目录；
- 最终风险知识根目录；
- 风险知识统计目录；
- 模型名称和接口地址；
- 模型认证配置；
- 最大并发数；
- 单条评分总时限；
- 最大重试次数；
- 检查点间隔。

`RiskRelevanceModelConfig` 将一次运行的配置封装为不可变对象，`from_env()` 支持环境变量覆盖，`validate()` 检查地址、密钥、并发、时限和重试参数是否合法。日志使用 `sanitized_api_url` 避免输出地址中的敏感查询信息。

### 6.4 `risk/indicator_tree.py`

该文件负责读取和解释 `risk2file_tree.json`。

主要数据对象包括：

- `MappingSource`：地区、映射文件名、原始文本和“已找到”文件名；
- `MappedFile`：规范化后的唯一文件及其多个映射来源；
- `IndicatorContext`：指标序号、名称、描述、风险类型和映射文件集合。

主要逻辑包括：

1. 校验三级指标序号必须是四段点分数字，并以 1 至 6 开头。
2. 校验风险树根节点、指标叶节点和序号唯一性。
3. 读取指标描述和六类风险根类型。
4. 递归提取映射文件叶节点中的“已找到”值。
5. 忽略“已找到”为空的映射项。
6. 清理文件路径、扩展名、空白和大小写，形成稳定查询键。
7. 生成含扩展名和不含扩展名的查询变体。

`list_indicator_numbers()` 返回按数字层级排序的全部三级指标；`load_indicator_context()` 返回单指标完整上下文；`load_indicator_contexts()` 一次读取并返回全部已校验上下文，供全量处理和统计复用。

### 6.5 `risk/graph_query.py`

该文件根据阶段一取得的映射文件名，在五类 Neo4j 标签中查询对应文件子图。

查询时以节点 `filename` 属性为主要依据，兼容列表和单值形式，并使用规范化文件名变体进行候选匹配。命中节点之后，只保留命中节点集合内部的关系。

结果按“映射文件、图谱类别”划分为 `GraphFilePartition`，并在 `GraphQueryResult` 中汇总：

- 命中的文件子图；
- 未命中的文件键；
- 同一文件跨多个类别命中的情况；
- 无法归入文件子图的关系数量；
- 实际查询过的标签。

该文件只查询和分区，不生成自然语言知识。

### 6.6 `risk/generation.py`

该文件实现风险知识阶段一，公开入口为 `generate_risk_indicator_knowledge()`。

主要流程如下：

1. 从指标树加载指标和映射文件。
2. 调用 `graph_query.py` 查询文件子图。
3. 根据图谱类别选择中文法规、国家标准、英文法规或合规指引转换器。
4. 为每个文件子图建立独立工作目录并执行转换。
5. 从 TXT 读取知识正文，从 JSONL 读取可用的转换器元数据。
6. 生成稳定 `knowledge_id`，合并重复知识的映射来源。
7. 记录文件命中、未命中、跨标签命中、关系问题和分类统计。
8. 通过暂存目录原子发布单文件 JSON 和汇总 `all.json`。

默认产物位于：

```text
temp/risk/<三级指标序号>/<文件名_短哈希>.json
temp/risk/<三级指标序号>/all.json
```

阶段一不调用大模型，生成的每条知识初始评分状态为 `pending`。

### 6.7 `risk/ranking.py`

该文件实现风险知识阶段二、单指标完整流程和全指标完整流程。

#### 关联度评分

`rank_risk_indicator_knowledge()` 读取阶段一 `all.json`，每次把一条知识和指标描述提交给模型。模型只允许返回 0.00 至 1.00 的关联度和非空原因。代码严格校验 JSON、分数范围和原因字段，并区分可重试与不可重试错误。

评分任务共享异步 HTTP 客户端，并通过信号量限制并发。处理过程中按检查点间隔原子回写 `all.json`，使中断后的已有成功评分可以被阶段二单独调用复用；`force=True` 时重新评分全部知识。

#### 排序与发布

评分成功的知识排在失败知识之前，并按关联度从高到低排序。同分时中文知识优先，再按原始顺序和知识编号保持稳定。评分和原因保留在 `all.json`，最终 `data/risk/<指标>/all.txt` 只写知识正文。

#### 单指标完整处理

`process_risk_indicator_knowledge()` 先在线程中执行阶段一，再异步执行阶段二，返回两阶段统计和产物路径。

#### 全指标完整处理

`process_all_risk_indicator_knowledge()` 顺序处理所有三级指标，单指标内部并发评分，并持续更新 `data/risk/处理汇总.json`。它使用跨进程文件锁，避免相同输出目录的全量任务同时运行。

默认断点续跑规则为：最终 `all.txt` 存在且包含非空知识时跳过；最终成果无效时，即使阶段一临时目录已有数据，也重新执行对应指标；`force=True` 时重跑全部指标。

文件写入采用临时文件加原子替换，并针对 Windows 文件短暂占用执行有限次数重试。

### 6.8 `risk/statistics.py`

该文件实现纯本地风险指标知识统计。它一次读取风险映射树，逐项校验 `temp/risk/<三级指标序号>/all.json`，并构建风险根节点、一级指标前缀、二级指标前缀和三级指标的完整统计层次。

三级指标按实际唯一知识标识计数。上级节点按规范化来源文件聚合后代知识，同一文件被多个指标引用时只计一次；若同一文件在不同指标中的知识集合不一致，则采用并集避免漏计，同时把差异写入冲突诊断。缺失和损坏的阶段一成果仍保留在层次树中，使覆盖率和完整性可以被直接判断。

默认统计写入 `data/stats/知识条目数统计.json`。该模块不访问 Neo4j 和模型服务，也不修改阶段一或最终风险知识成果。

## 第七章 `risk/tree` 指标树资源目录

### 7.1 `risk/tree/__init__.py`

该文件使用模块级 `__getattr__` 延迟加载指标描述同步工具。普通知识生成只需读取 JSON，不会因为导入 `risk.tree` 就立即加载 `openpyxl`，从而减少不必要的启动开销和依赖耦合。

### 7.2 `risk/tree/risk2file_tree.json`

该文件是风险知识处理的核心数据资源，按六类风险组织三级指标。每个指标叶节点保存：

- 三级指标序号；
- 指标描述；
- 按地区和文件组织的映射树；
- 映射文件原始文本；
- 与实际图谱文件对应的“已找到”值。

风险知识阶段一只处理“已找到”非空的文件。

### 7.3 `risk/tree/indicator_description_sync.py`

该文件用于从企业合规风险指标工作簿向风险映射树同步指标描述。

工具预置六个工作表与六类风险根节点的对应关系。同步前会校验：

- 六个目标工作表是否存在；
- 指标编号和指标描述列是否可识别；
- 指标编号格式及所属类别是否正确；
- 工作簿和风险树的指标编号集合是否一致；
- 风险根类型是否一致；
- 是否存在重复指标或空描述；
- 写入前后除“指标描述”外的内容是否保持不变。

`sync_indicator_descriptions()` 默认只检查；`write=True` 时在全部校验通过后原子写回 JSON。文件也可作为命令行工具执行，并以 JSON 输出检查或写入报告。

## 第八章 `data` 正式成果目录

### 8.1 `data/type`

该目录保存 `process_graphs_by_type()` 发布的五类正式知识：

```text
法律法规条款.txt
国家标准.txt
行政监管规则.txt
英文法规.txt
合规指引.txt
知识条目统计.json
```

五个 TXT 均采用 UTF-8，每行一条知识。统计 JSON 记录生成时间、处理状态、各类节点数、关系数、来源文件数、知识条目数和总知识条目数。

这里是面向分类检索和总体知识库使用的正式成果，不应作为临时调试目录。

### 8.2 `data/risk`

该目录保存风险指标最终成果：

```text
data/risk/
├── 处理汇总.json
└── <三级指标序号>/
    └── all.txt
```

每个 `all.txt` 汇总多个映射文件产生的知识，并按关联度排序；文件中只保存知识正文。`处理汇总.json` 保存全量任务状态、实际处理数、跳过数、成功数、失败数、知识数量、评分数量及逐指标结果。

目录是否存在并不能单独证明指标已完成。全量断点续跑以非空的最终 `all.txt` 为完成依据。

### 8.3 `data/stats`

该目录保存风险指标知识的层级统计 JSON。统计同时提供三级指标直接数量、上级文件去重数量、后代指标覆盖情况、缺失或无效成果以及文件一致性诊断。它是依据 `temp/risk` 生成的可重复派生成果，不替代 `data/risk` 中供检索使用的知识正文。

## 第九章 `temp` 临时工作目录

### 9.1 目录定位

`temp` 保存导出、转换、阶段一汇总和评分检查点。这里的数据用于运行中转和问题审查，可能在后续任务中被覆盖，不应替代 `data` 下正式成果。

### 9.2 `temp/json`

保存通用单图流程导出的 `node.json` 和 `edge.json`。调用 `clear_temp_dir()`、`export_graph()`、`process_graph()` 或 `process_graph_v2()` 时可能清理和覆盖这两个文件。

### 9.3 `temp/txt`

保存转换器生成的逐行知识文本。文件名通常由 `graph_type` 参数确定。批处理和风险知识阶段一会在各自暂存目录运行转换器，不依赖这里已有的 TXT。

### 9.4 `temp/jsonl`

保存国家标准、英文法规和合规指引转换产生的逐条知识元数据。JSONL 每行是一个 JSON 对象，适合流式读取和审查来源信息。中文法规 v2 当前不生成 JSONL。

### 9.5 `temp/csv`

保存转换统计。不同转换器会记录知识类型、来源文件、跳过原因、关系问题、过滤字段或校验问题。它用于检查转换质量，不是最终知识正文。

### 9.6 `temp/risk`

每个三级指标目录保存单文件 JSON 和汇总 `all.json`。`all.json` 在阶段一生成，在阶段二持续补充关联度、原因、状态和统计。

根目录中的 `.process_all.lock` 是跨进程协调文件。锁是否生效由操作系统文件锁决定，文件本身存在不表示任务一定正在运行，不应把它视为业务数据。

### 9.7 `temp/run_all_risk_indicator_knowledge.py`

该脚本为 `process_all_risk_indicator_knowledge()` 提供可直接执行的命令行入口。

支持参数包括：

- 模型评分最大并发数；
- 是否强制重跑全部指标；
- 是否在首个指标错误后停止；
- 自定义风险树；
- 自定义临时成果和最终成果根目录；
- 日志级别。

脚本负责建立项目导入路径、初始化日志、运行异步接口并输出精简汇总。正常成功返回退出码 0，存在部分失败返回 1，用户中断返回 130。

## 第十一章 缓存目录与维护边界

### 11.1 `__pycache__`

根目录及各代码子目录下的 `__pycache__` 由 Python 解释器自动生成，内部 `.pyc` 文件用于加快模块加载。它们可以在程序停止后删除，随后会自动重建。

缓存文件不应作为源码提交依据，也不应参与知识条目数量和成果完整性统计。

### 11.2 代码、配置、临时成果和正式成果的边界

| 类型 | 位置 | 维护原则 |
| --- | --- | --- |
| 业务代码 | 根目录、`batch`、`converters`、`graph`、`risk` | 通过代码评审和测试维护 |
| 数据配置 | `risk/tree/risk2file_tree.json` | 修改前校验指标、映射文件和六类风险口径 |
| 临时成果 | `temp` | 可重建，允许被流程覆盖 |
| 正式成果 | `data` | 由正式接口发布，避免手工混入无关文件 |
| 设计和任务记录 | `docs/design`、`docs/tasks` | 记录规则和实施过程 |
| 核心使用文档 | `docs/核心文档` | 随公开接口和目录结构变化同步更新 |

## 第十二章 典型数据流

### 12.1 单图谱转换

```text
Neo4j 指定标签
  → graph/exporter.py
  → temp/json/node.json、edge.json
  → converters/router.py
  → 对应专用转换器
  → temp/txt、temp/jsonl、temp/csv
```

### 12.2 五类知识库更新

```text
五类固定 Neo4j 标签
  → batch/processor.py 独立暂存
  → 各类别专用转换器
  → 数量一致性校验
  → data/type 五个 TXT
  → data/type/知识条目统计.json
```

### 12.3 三级风险指标知识生成

```text
risk/tree/risk2file_tree.json
  → risk/indicator_tree.py 提取指标和“已找到”文件
  → risk/graph_query.py 查询五类 Neo4j 文件子图
  → risk/generation.py 调用类别转换器
  → temp/risk/<指标>/all.json
  → risk/ranking.py 调用模型评分和排序
  → data/risk/<指标>/all.txt
```

### 12.4 全量断点续跑

```text
全部三级指标
  → 检查 data/risk/<指标>/all.txt
  → 已有非空最终知识：跳过
  → 最终知识缺失或为空：重跑阶段一和阶段二
  → 持续更新 data/risk/处理汇总.json
```

### 12.5 风险层级知识统计

```text
risk/tree/risk2file_tree.json
  + temp/risk/<指标>/all.json
  → risk/statistics.py 校验三级指标成果
  → 父级按规范化来源文件去重聚合
  → data/stats/知识条目数统计.json
```
