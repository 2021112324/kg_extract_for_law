# 提示词生成步骤
## 第一步
根据法律判决书的示例内容，生成法律判决书的结构描述。
例如：
1. 询问大模型，得出一审民事判决书的一般结构：
民事一审判决书
[首部信息]
  ├─ 法院名称
  ├─ 文书类型（民事判决书）
  ├─ 案号
  ├─ 原告基本情况
  ├─ 被告基本情况
  └─ 第三人（如有）
→ [诉讼请求]
    ├─ 请求给付（金钱 / 行为）
    ├─ 请求确认权利义务
    └─ 请求承担违约 / 侵权责任
    （可多项并列）
→ [事实与理由]
    ├─ 原告事实陈述
    ├─ 原告理由说明
    └─ 被告答辩意见
    （部分案件可能无完整答辩）
→ [争议焦点归纳]（可选，但高频）
    ├─ 法律关系是否成立
    ├─ 责任主体是否适格
    ├─ 是否存在违约 / 侵权
    ├─ 损害是否存在及范围
    └─ 责任承担方式
→ [本院查明]
    ├─ 事实认定
    ├─ 证据采信情况
    └─ 对争议事实的认定结论
    （部分案件与“本院认为”合并出现）
→ [本院认为]（核心裁判段）
    ├─ 法律关系性质认定
    │    ├─ 合同关系
    │    ├─ 侵权关系
    │    ├─ 不当得利 / 无因管理
    │    └─ 其他民事法律关系
    │
    ├─ 构成要件分析
    │    ├─ 合同效力 / 履行 / 违约
    │    ├─ 侵权行为 / 过错 / 因果关系
    │    └─ 特殊规则（如代位权、连带责任）
    │
    ├─ 责任承担方式
    │    ├─ 给付责任
    │    ├─ 赔偿责任
    │    ├─ 停止侵害 / 消除影响
    │    └─ 其他责任形式
    │
    └─ 法律依据适用
         ├─ 实体法条
         └─ 司法解释
→ [判决结果]
    ├─ 支持全部诉讼请求
    ├─ 部分支持诉讼请求
    ├─ 驳回诉讼请求
    └─ 诉讼费用承担
→ [尾部信息]
注意：大模型提供的结构描述仅能用于参考，事实证明其并不总是能准确描述法律判决书的结构。

## 第三步
设计其余各结构部分的schema提示词（允许提示词为空，表示该结构无抽取内容）
示例：
```python
# 一审民事判决书
# 诉请主张
defense_claim_schema = {
    "chunks": [
        defense_claim.get("name")
    ],
    "nodes": """
## 诉请主张
### 描述
当事人在诉讼中向法院提出的具体权利请求。涵盖原告的诉讼请求和被告的反诉请求。
### 属性
- 提出方：提出该主张的当事人
- 请求编号：该主张请求在当事人一系列诉请主张中的编号
- 请求类型：请求的法律性质分类。枚举值：金钱给付 / 行为给付 / 确认之诉 / 形成之诉
- 请求内容：该主张请求的具体内容
- 依据事实：支持该请求的核心事实陈述（原文截取）
- 程序状态：程序状态是指该诉请主张在诉讼程序法上所处的阶段或须满足的前置程序条件。

## 答辩主张
### 描述
当事人针对对方请求提出的防御或反制意见。涵盖被告对原告诉请的答辩、原告对被告反诉的答辩。
### 属性
- 提出方：提出该主张的当事人
- 答辩编号：该答辩在当事人一系列答辩中的编号
- 答辩内容：该答辩的具体内容
- 答辩性质：对该请求的回应态度。枚举值：承认 / 否认 / 抗辩 / 反诉
- 否认对象：当答辩性质=否认时，细分。枚举值：否认事实 / 否认权利 / 否认法律适用
- 抗辩事由：当答辩性质=抗辩时，事由类型。枚举值：时效抗辩 / 履行抗辩 / 抵销抗辩 / 合同依据抗辩 / 不可抗力
- 反诉请求：当答辩性质=反诉时，反诉的具体内容
- 答辩理由：支持该答辩意见的核心陈述（原文截取）

## 争议焦点
### 描述
诉辩主张中暴露出的、双方存在实质性分歧的核心问题。
### 属性
- 争议内容：争议的具体问题
- 核心行为: 关键动作描述，如“擅自运营”“绕过接口限制抓取数据”
- 争议类型: 分类标签，如“行政处罚争议”“合同履行纠纷”“数据抓取侵权”等

## 诉讼参与者
### 描述
表示在诉讼中承担某法律职能或身份的自然人或组织，这里是指提出某一具体诉讼请求或答辩主张的当事人。
### 属性
- 名称: 该人员或组织的真实姓名，通常为实名登记信息。
- 性别: 根据上下文推断或直接记载的性别信息。
- 职业: 自然人的职业，如律师。
- 出庭情况: 是否实际到庭参加庭审或询问，影响程序合法性判断。
- 参与阶段: 该人员在哪一审判阶段参与了诉讼。
- 诉讼角色: 自然人或组织在诉讼案件中的参与身份，包括上诉人、被上诉人、委托诉讼代理人、法定代表人、一审第三人、审判长、审判员、法官助理、书记员等。
- 所住地/注册地: 自然人的实际所住地或组织注册地址。
- 其他信息: 除上述信息外的其他相关信息，如身份证号、民族、出生日期、法律状态等。

## 法规条款依据
### 描述
指在行政判决书中被法院实际引用、作为裁判支持的法律、法规或司法解释中的具体条、款、项等，代表最小单位的法律适用依据。
### 属性
- 法规名称: 法规的正式名称,如《中华人民共和国专利法》，不包含具体的条款
- 案例条款编号: 法律规章的具体条款编号，如第十条，第十二条第八款
- 法规条款内容: 法律规章的具体条款内容
- 法规条款摘要: 法规条款的核心内容
- 适用目的: 该依据在本案中所起的作用，如\"用于认定程序违法\"\"作为撤销处罚的理由\"
- 法规层级: 法律效力层级，如法律、行政法规、司法解释
- 法规方向: 法规调整的法律关系方向，如刑事责任、行政处罚
- 时效性: 法规当前状态，如\"现行有效\"\"已废止\"\"已修订\"
    """,
    "edges": """
## 提出
```

# 提示词使用流程
## 第一步
根据法律文书的结构，构建法律文书的提示词，对法律文本进行原文分块归类，每个结构对应原文的一部分内容

```python
def legal_structure(self):
    temp_structure_list = [
        self.head,
        self.participant,
        self.trial_process,
        self.defense_claim,
        self.fact,
        self.court_reasoned,
        self.judgment,
        self.right_to_appeal,
        self.organization_and_date_of_trial,
        self.appendix_french
    ]
    structure_description = "一份完整的民事判决书通常包含以下结构部分："
    structure_list = []
    for structure in temp_structure_list:
        if not structure:
            continue
        structure_description += "\n - " + structure["name"] + ": " + structure["description"]
        structure_list.append(structure["name"])
    return structure_description, structure_list

def chunking_prompt_v2(self) -> str:

""" + str(legal_structure) + """
```
