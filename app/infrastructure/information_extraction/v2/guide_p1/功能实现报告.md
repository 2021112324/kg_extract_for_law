# 分点格式合规指引知识图谱抽取功能实现报告

## 1. 任务结论

本任务应新增一套独立的分点格式合规指引抽取流程，不宜直接改造或复用现有 `guide_extract`。旧模块以“法规文件、法条、条款单元”为本体，依赖“第X条”识别正文；本批数据则主要是规划、工作方案等指导性文件，以“一、”“（一）”、专栏和附件组织内容，语义重点也不是法定义务和法律后果，而是政策目标、行动任务、指导性要求、禁止性要求和保障安排。

建议采用两阶段方案：第一阶段通过确定性规则恢复文件结构和原文边界，第二阶段在结构节点范围内使用 LangExtract 和本体 Schema 抽取最小知识单元。最终图谱同时保留文件结构和可生成知识条目的语义对象，并对模型失败、越界字段、非法关系和不受控取值进行真实统计。

## 2. 数据审查结果

### 2.1 目录现状

任务指定目录：

`D:\CogmAIT\8.1项目\8.1数据\合规风险指标映射数据\v1_819\op2_风险映射添加\风险数据\中国\合规指引\分点格式\行政监管规则`

该叶路径当前不存在。实际可供分析的 10 份 `.txt` 文件直接位于“分点格式”目录，文件规模约为 2.4 万至 8.9 万字节。因此本报告以该目录中的实际样本为依据。后续程序不会自动回退父目录；传入不存在路径或无文件目录时均应明确报错，避免误处理其他类别数据。

### 2.2 内容类型

样本主要包括国家级规划和综合工作方案。文本通常由以下部分组成：

1. 文首合规风险类型标注。
2. 通知或印发说明，包括文号、发布单位、日期和收文对象。
3. 规划或方案正文。
4. 多级标题和分点内容。
5. 专栏、附件或其他补充内容。

同一文件中可能同时出现现状分析、指导思想、总体目标、重点任务、量化指标、责任分工和保障措施。不同内容的知识价值和约束强度不同，不能把每个自然段都统一解释为企业必须履行的法律义务。

### 2.3 结构特征

实际样本具有以下共性：

- 一级标题多采用“一、标题”，二级分点多采用“（一）标题+正文”。
- 部分文件在不同篇章重新从“一、”开始，编号本身不能作为全文件唯一键。
- 有的分点标题与正文同处一行，有的标题单独成行。
- 一个分点内可能连续出现多项行动、多个量化目标和多组责任单位。
- 专栏常承载重点工程、主要指标或任务清单，不能被当作普通正文丢弃。
- 附件并无固定格式。当前样本仅有一份文件出现附件，其中既有字段较完整的表格行，也有因原表合并单元格而缺少重复字段的摊平文本；不同附件的知识价值也不一致。
- 通知标题与正文标题可能不同，文件级实体应以正文对应的实际指引文件为主，同时保留通知外壳信息。
- 责任分工常位于分点末尾的括号中，应与对应行动保持关联，不能混入行动摘要后丢失角色语义。

## 3. 现有代码适用性审查

### 3.1 `guide_extract`

现有模块的结构切分器只识别章、节和“第X条”，没有匹配到法条时直接失败；prompt 和 schema 也围绕法条、条款单元、法律后果和引用依据设计。因此，它无法稳定解析本批数据，也会把规划性表达错误套入法规语义。

结论：仅可参考其项目基础类调用方式，不能复用其切分逻辑和本体。

### 3.2 `national_standard`

国家标准模块将结构解析和 LLM 语义抽取分离，第一阶段保留树结构和资源信息，第二阶段在结构节点边界内抽取语义对象。这一总体架构适合本任务，可复用其两阶段组织方式、结构校验思路、schema 白名单提取和图谱构建方式。

结论：作为本任务的主要流程参考，但分点标题规则、知识类型和图谱本体需要重新设计。

### 3.3 `en_law_v3`

英文法规 V3 对 prompt 进行了文件级、条文级和最小单元级拆分，并具备配置对象、受控并发、严格/宽松模式、中间结果留存和目录级统计。这些工程能力适合迁移到 `guide_p1`。

结论：重点参考其 `prompt` 目录组织、并发调用、结果标准化、失败记录和可审查产物设计。

## 4. 两阶段抽取流程

### 4.1 第一阶段：结构解析

第一阶段不调用大模型，不产生政策语义节点，只负责把原始文本整理为稳定、可核验的结构化输入。

处理步骤如下：

1. 输入预检：确认路径存在、文件类型受支持、目录中存在可处理文件。
2. 文本读取与轻量清洗：处理编码、空白、全角符号和异常换行，同时保留原始文本。
3. 文首信息识别：提取合规风险类型标注和文件信息候选区域。
4. 通知外壳与正文识别：区分印发通知和指引正文，确定正文标题及起始位置。
5. 层级恢复：按出现顺序识别一级标题、二级分点、其他编号项和专栏，构建正文结构树；遇到附件、附录或附表时记录边界并停止附件内容解析。
6. 内容块构建：把标题、正文和必要的上级语境组成第二阶段可用的边界块。
7. 结构校验：检查正文是否存在、节点顺序是否有效、父子关系是否闭合、原文范围是否可回溯。

第一阶段每个正文结构节点至少保存结构类型、显示编号、标题、节点内容、父级、顺序、完整路径、起止行和来源文件。节点 ID 不直接使用“一、”“（一）”等编号，而由文件身份、出现顺序、结构路径和内容摘要确定，从而允许编号重新开始。附件只在审查结果中保存编号、标题、原文范围和跳过状态，不构建附件内容节点。

### 4.2 第二阶段：本体约束语义抽取

第二阶段包括一次文件级抽取和若干内容块级抽取。

文件级抽取用于确认指引文件名称、文号、发布单位、发布日期、文件类型、适用范围和明确引用的制定依据。输入只包含文件头、正文标题和必要的开篇内容，避免整份长文影响文件信息判断。

内容块级抽取以第一阶段形成的分点或语义完整块为边界。模型根据当前原文和上级标题判断该块是否包含可形成知识条目的政策命题，并抽取知识类型、约束强度、适用对象、行动、条件、期限、量化目标、责任主体和引用依据。模型不得跨分点补写，也不得根据常识推断未出现的责任、风险或法律依据。

所有内容块通过共享信号量并发调用。单个调用异常、输出不可解析或违反 schema 时，必须保留对应输入、错误和重试信息；不能根据标题或关键词补造一个“看起来正确”的知识单元。

## 5. 最小知识单元设计

### 5.1 定义

最小知识单元是：在补入必要的上级标题语境后，能够独立表达一项政策目标、行动任务、指导性要求、禁止性要求或保障安排的最小完整命题。

它应尽可能回答以下问题：

- 面向谁或什么对象；
- 提出了什么行动、约束或目标；
- 在何种范围或条件下适用；
- 是否存在期限或量化目标；
- 原文明确由谁负责或落实。

这些要素并非每条都必须出现，但知识单元必须保持语义完整，不能只剩下脱离上文的动词、列举项或数值。

### 5.2 拆分规则

应拆分的情况：同一分点内存在多个可以独立成立的行动，或不同动作对应不同对象、条件、期限、目标和责任分工。

不应拆分的情况：多个列举项共享同一主干，单独取出后无法判断主体、动作或适用条件；量化数字只是前述行动的目标；责任单位只是前述任务的责任说明。

背景、发展现状、编制目的和一般原则主要保留在结构节点中。除非其中形成明确、可检索的政策目标或行动安排，否则不生成知识单元。这样既覆盖原文，又避免把一般描述伪装成合规要求。

### 5.3 知识条目生成条件

知识单元应具备原文、结构路径和明确语义类型，并至少包含行动或目标中的一项，才能标记为知识条目候选。后续自然语言转写时，可组合文件名称、结构路径、适用对象、行动、条件、期限、目标和责任主体形成完整条目，而不需要再次从整段原文推断。

### 5.4 附件处理策略

首版默认跳过附件、附录和附表正文。解析器识别相关边界后，只记录附件编号、标题、起止行和“已跳过”状态，不调用大模型、不生成附件知识单元，也不把附件内容写入正式图谱。原始文件仍完整保存，因此不会造成原始数据不可追溯。

采用该策略的原因是当前附件样本较少且格式不固定，部分内容来自表格摊平，合并单元格语义已经丢失；同时不同附件的合规知识价值差异较大。将其直接纳入通用分点抽取会显著增加误抽和错误关联风险。后续如确认某类附件具有稳定结构和明确知识价值，应设计独立的附件或表格抽取流程，而不是放宽首版正文规则。

“专栏”不属于本策略的跳过范围。专栏通常包含主要指标、重点工程或任务安排，应作为正文结构节点继续抽取。

## 6. 图谱本体建议

### 6.1 节点类型

| 节点类型 | 作用 |
| --- | --- |
| 合规指引文件 | 保存整份规划、方案或指导文件的文件级信息 |
| 指引结构节点 | 保存正文篇章、分点和专栏的层级及原文 |
| 指引知识单元 | 保存可检索、可转写的最小政策命题 |
| 责任主体 | 保存原文明确的牵头、配合或落实主体 |
| 量化目标 | 保存与知识单元关联的数值目标、比例、期限或数量要求 |
| 引用依据 | 保存原文明确引用的公开文件或规范依据 |

### 6.2 关系类型

| 关系类型 | 语义 |
| --- | --- |
| 包含 | 文件与结构节点、结构节点与下级结构节点之间的层级关系 |
| 提出 | 结构节点提出某个知识单元 |
| 由其负责 | 知识单元与原文责任主体的关系 |
| 设定目标 | 知识单元与量化目标的关系 |
| 引用 | 文件或知识单元对明确依据的引用关系 |

### 6.3 受控语义

建议将知识类型收敛为政策目标、行动任务、指导性要求、禁止性要求和保障措施。约束强度用于区分强制任务、指导性要求、倡导性建议和目标性安排。对无法可靠判断的内容保留原文并产生警告，不新增“其他”类动态值。

合规风险类型只能使用项目既定六类值，并以字符串数组保存。文首已明确标注时可以继承到知识单元；未明确标注时不得仅凭主题推断。

## 7. Prompt 与 Schema 设计

建议采用以下目录：

```text
guide_p1/
  __init__.py
  config.py
  io_utils.py
  structure_parser.py
  extractor.py
  graph_builder.py
  validator.py
  stats.py
  prompt/
    __init__.py
    schema.py
    prompt.py
    example.py
  test/
```

文件级和内容块级分别定义 schema、prompt 和 few-shot 示例。prompt 应明确角色、任务边界、输入结构、判定步骤、允许输出、禁止事项和解析兼容要求。示例需要同时覆盖正确拆分、保持共享主干、不把背景抽成要求、不把责任单位变成行动内容等情况。

Schema 不仅提供给模型，还应由代码解析出实体属性白名单、关系类型和合法三元组。这样修改本体时，提示约束和后处理校验能够保持一致，避免再次出现动态长句属性或关系端点失控。

## 8. 图谱组装与质量控制

第一阶段产生的文件结构节点可直接进入上下文图谱；第二阶段只补充通过校验的语义节点。图谱构建时执行以下检查：

1. 实体类型属于当前 schema。
2. 节点属性属于对应实体白名单。
3. 关系起点、谓词和终点符合合法三元组。
4. 知识类型、约束强度和风险类型属于受控集合。
5. 知识单元能够回到一个真实结构节点和原文范围。
6. 量化目标、责任主体和引用依据均有明确原文来源。
7. 文件内重复节点按规范化名称和来源范围合并，不能仅凭跨文件同名强行合并。

可明确判断的问题由规则过滤或规范化；无法确认的问题记录警告并保留审查信息。正式图谱不得包含模型自行生成的 schema 外字段。

## 9. 失败处理、日志与统计

默认采用严格模式：文件级抽取失败，或任一计划抽取的内容块在重试后仍失败，该文件不能标记为完整成功。系统仍保存第一阶段结构、已完成调用、失败块、错误信息和统计，便于修复后定点重跑。

模型成功返回空语义结果可以表示该块仅需保留结构；但对包含明显任务、要求或目标信号的内容块，空结果应记录强警告，进入抽样审查。

统计至少包括：文件总数、成功文件数、错误数、抽取错误数、文件处理错误数、弱警告数、强警告数、结构节点数、计划抽取块数、LLM 成功块数、LLM 失败块数、知识单元数、节点数和边数。错误和警告必须同时保留具体文件及结构块定位，不能因为最终写出了若干结构节点就把错误数统计为零。

## 10. 输出设计

每份文件建议输出四类结果：

- `split`：第一阶段结构树、原文范围和结构校验。
- `extraction`：第二阶段调用输入、成功结果、失败结果和调用统计。
- `kg`：通过校验的节点、关系和图谱元数据。
- `summary`：文件级状态、数量、错误和警告。

目录批处理额外输出总汇总。审查字段和大段中间输入保留在本地 JSON；后续 Neo4j 适配时只转换业务节点、关系和必要来源属性，嵌套对象按节点化或 JSON 字符串方式处理。

## 11. 并发方案

采用 `asyncio.gather(..., return_exceptions=True)` 执行内容块任务，并用共享 `Semaphore` 限制 LLM 并发。建议默认并发数为 5，可通过环境变量调整。首版按文件顺序处理、文件内分点并发，避免大批文件同时展开造成模型服务过载，也便于保持单文件统计互不污染。

## 12. 测试与验收

离线测试应覆盖：

1. 空目录和不支持文件类型。
2. 通知外壳与正文标题识别。
3. 一级、二级分点和编号重新开始。
4. 标题与正文同一行、正文专栏和附件跳过边界。
5. 超长复合分点及共享主干。
6. 量化目标和责任分工后缀。
7. Schema 白名单、非法三元组和受控枚举。
8. 模型异常、空结果、严格失败和统计口径。
9. 节点边统一格式及可审查四阶段输出。

真实模型验收先选取少量具有代表性的分点，人工核对知识单元是否完整、是否过度拆分、是否把背景误抽为要求，再执行 10 份样本的目录级试跑。验收通过的关键标准是：结构覆盖稳定、知识单元可独立转写、语义节点全部来自成功模型结果、失败统计真实、正式图谱不含 schema 外字段。

## 13. 建议实施顺序

1. 完成输入发现、结构解析器和第一阶段测试。
2. 确认首版本体及最小知识单元示例。
3. 完成模块化 prompt、schema 和 LangExtract 调用。
4. 完成 schema 驱动校验、图谱组装和中间产物保存。
5. 完成严格失败、并发、日志和汇总统计。
6. 执行离线测试与小规模真实模型测试。
7. 在抽取结果通过审查后，再单独接入服务层接口和 Neo4j 入库。

## 14. 总体判断

该方案与实际样本结构匹配，也能继承现有项目中已经验证的两阶段抽取、LangExtract prompt 组织、并发控制和错误统计能力。最关键的改动不是增加更多标题正则，而是把“文档结构块”和“可生成知识条目的最小政策命题”分开建模：前者保证原文覆盖和上下文，后者保证检索粒度和知识质量。建议按本报告实施首版，并在真实模型小样本结果审查后再冻结最终字段细节。
